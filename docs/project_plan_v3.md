## 1. 版本目标

v2 实现了"常驻桌面 + 换整张立绘"。实际使用后发现两个问题：动作切换生硬、不够可爱。v3 的目标是：

1. **桌宠本体达到 Coopanion 的水准**：采用分层网格骨骼和弹簧物理。表情、动作连续变化，不再切换整张图；可以沿屏幕底边走动、拎起来甩、摸头。
2. **大脑像 surfcore 一样"有生活"**：记忆会逐渐模糊遗忘，另有一份永久存档；会从记忆里提炼出想做的事，再主动来找你；有作息和专注模式。
3. **语音像 Open-LLM-VTuber 一样自然**：千问声线；外放时也能开口打断，不会被自己的声音触发。
4. **手能干活**：本机文件与网页、博客与开发、操作电脑、QQ / B站。所有动作都要分级审批，并留审计记录。
5. **花销可控**：按用途统计词元用量，设每日额度，到 80% 提醒、到 100% 停止。

## 3. 总体架构

仍然是**单个 Python 进程**，后台任务跑在 QThread 中。按职责分为六个包：

```text
aicompanion/
  body/        桌宠本体：骨骼渲染（WebEngine + Pixi 网格）、物理与行为、整屏透明窗口、气泡
  brain/       人格与记忆：角色卡、衰减记忆卡、全量存档、收件箱、目的机制、情绪关系、作息
  voice/       语音：千问 TTS、ASR 后端（云端 / 本地）、回声消除与打断、口型数据
  agent/       干活：工具循环、工具注册、审批、审计、MCP 客户端、各类工具
  usage/       词元计量、价目表、每日额度、看板数据
  ui/          聊天面板、设置、控制台页（用量、记忆、审计、目的）
```

两条对话通路（借鉴 surfcore）：

| 通路 | 用途 | 词元成本 |
| --- | --- | --- |
| **陪伴通路** | 日常闲聊、主动搭话、气泡台词：角色卡 + 记忆卡 + 最近对话，直接调用模型，**不带工具表** | 低 |
| **agent 通路** | 用户要求做事、或陪伴通路判断"需要动手"时升级：带工具表的多步循环，有审批 | 高，计入独立额度 |

陪伴通路的回复里可以带一个"需要干活"的结构化标记（例如 `<task>整理下载文件夹</task>`），界面据此询问"要我动手吗？"，你同意后才进入 agent 通路。

## 4. 桌宠本体（body）

### 4.1 渲染：自研分层网格骨骼

- **技术**：继续用已验证的 Qt WebEngine + Pixi（艾米莉娅网格动画就在用）。每个部件是一张贴图，切成 N×M 网格，挂在变形器树上。变形器有两种：
  - **rot**：绕支点旋转、缩放、平移
  - **warp**：在一个矩形内的位移场

  每帧在 JS 中计算顶点。
- **为什么不用纯 Qt**：QPainter 无法做逐三角形纹理映射；QML ShaderEffect 可以做，但要逐部件写着色器、离线编译。WebEngine 方案风险最低。
- **代价与对策**：WebEngine 常驻内存约 200–300 MB。P1 结束时实测；超过预算再评估 QML 方案。
- **模型格式 `AICompanionRig v1`**（自定义 JSON）：
  - `parts`：每个部件的贴图、在骨骼空间的矩形、网格密度、层级、父变形器、混合模式
  - `deformers`：rot / warp 树
  - `springs`：头发、裙子、尾巴、鳍、呆毛、头、手臂
  - `expressions`：每种表情对应的眼睛、嘴巴、眉毛、腮红贴片或参数
  - `motions`：点头、摇头、挥手、鞠躬、跳、坐、睡等的参数时间线
  - `vocab`：给模型看的表情和动作词表
- **表情**：先做 9 种，与 Coopanion 大肥鱼的贴图套数一致：开心、喜爱、害羞、惊讶、困、晕、被拎、中性、思考。后续扩到 18 种。
- **说话**：口型由千问 TTS 播放音量驱动；纯文字时按字符节奏开合。

### 4.2 窗口与交互（借鉴 Coopanion）

| 项 | 做法 |
| --- | --- |
| 窗口 | 一个覆盖当前显示器工作区的透明置顶窗口，角色画在底边"地面"上；气泡、活动图标也在同一窗口里，不再另开小窗口 |
| 鼠标穿透 | 默认整窗穿透（Windows `WS_EX_TRANSPARENT`）；每 50 ms 读一次光标位置，落在身体或气泡的命中区时临时取消穿透 |
| 去边框 | `NoDropShadowWindowHint` + DWM 关圆角、关边框（v2.1 已写好，待合入） |
| 走动 | 沿底边走或跑，频率可调；`move_to(left / center / right / cursor)` 也提供给模型调用 |
| 拎起 / 甩出 | 拖动时钟摆式摆动，松手带速度飞出，重力落地；摔得重会晕几秒 |
| 戳 / 摸 | 单击是戳；鼠标在头上来回划是摸头。连戳会生气，摸头会眯眼 |
| 开场 | 启动时从屏幕顶部掉到底边 |
| 气泡 | 最多 3 个、最多 6 行；回复结束 1 秒后淡出，或 8 秒没有回复时淡出；点击关闭。用户说的话显示为虚线气泡 |
| 活动图标 | agent 在思考、读文件、搜索、写东西、操作电脑时，头顶冒出对应的小图标 |
| 夜间 / 专注 | 夜间模式降低亮度和音量；专注模式下不主动说话、不走动 |

### 4.3 动作由模型参与

- 角色卡里写入表情与动作词表。模型在台词中用标记，例如 `【开心】`、`<挥手>`，界面解析后执行，并从显示文字里去掉。
- 规则兜底：没有标记时，用情绪状态决定表情。

## 5. 大脑（brain，借鉴 surfcore）

### 5.1 记忆

| 层 | 内容 | 注入提示词 |
| --- | --- | --- |
| 收件箱 | 桌宠对话、QQ、B站、agent 结果的原始事件，只追加 | 否 |
| 衰减记忆卡 | 带重要度和清晰度（清楚 → 模糊 → 遗忘）的记忆；每日衰减；超容量时由模型压缩 | 是，按预算裁剪，并按隐私范围过滤 |
| 全量存档 | 同样的记忆，永不遗忘，只追加 | 否，只在控制台查看或按需召回 |

- 整理器每 10 分钟运行一次：读收件箱 → 先归档进全量存档 → 衰减 → 压缩 → 生成各场景的注入文本。
- 隐私范围：`pet` 是私下相处，`qq` 和 `bili` 是公开场合。桌宠里的私密内容默认不进入 QQ 和 B站 的提示词。
- 迁移：现有 SQLite `memories` 表的数据导入为"清楚"状态的记忆；你删除过的记忆（墓碑）继续生效，不会被重新记住。

### 5.2 目的机制（主动搭话）

- 每 60 秒检查一次是否到排程时间。到点时，从近期记忆里提炼候选的"目的"，类型有四种：想弄明白、想做、想分享、想向你要。
- 每天的次数有上限，深夜是安静时段，专注模式下暂停。
- **载体二选一**：桌宠（气泡加千问语音），或 QQ 私聊。桌宠不在线时可以回落到 QQ，但两边不会同时发。
- 历史、惦记的事、目标假设都存在角色目录下，可以在控制台查看。

### 5.3 情绪、关系、作息

沿用 v1 的情绪关系和每日信任上限，加上 surfcore 式的作息：几点困、几点醒、白天是否偶尔"出门刷 B站"。作息同时影响桌宠的表现。

## 6. 语音（voice）

| 项 | 方案 |
| --- | --- |
| TTS | 千问声线，按句流式合成并预取下一句（已有）；口型数据由播放音量生成，送给渲染器 |
| ASR | 云端：千问、智谱（已有）；本地：sherpa-onnx + SenseVoice（Coopanion 和 Open-LLM-VTuber 都在用），离线可用 |
| 外放打断 | 先实测两种方案，再选一种：① 收音和播放都放在 WebEngine 页面里，用 Chromium 自带的回声消除（`echoCancellation`）；② Python 侧 WebRTC AEC，以播放音频作为参考信号。两种都配合"播放期间提高 VAD 门槛"使用 |
| 收音方式 | 按住说话键、切换式收音、持续通话三种 |
| 语音引擎 | 先留在进程内；如果日后需要给 QQ 发语音条，再像 surfcore 那样拆成本机服务 |

## 7. 干活（agent）

### 7.1 核心

- 给 `OpenAICompatibleClient` 加上工具调用：流式解析 `tool_calls`，保留推理内容用于"思考摘要"。
- `AgentRunner` 运行在后台线程，单次任务有步数、单工具超时、总时长三重上限，可以随时打断。
- MCP 客户端（Python `mcp` 库）用于复用现成的工具服务器。外部工具默认归为"危险"级。
- 审批分三级：只读、可撤销、危险。审批以角色口吻用气泡发出，所有操作写入审计表，可撤销的操作可以撤销（细节见 v2 §9，沿用）。

### 7.2 工具分组

| 组 | 首批工具 | 审批要点 |
| --- | --- | --- |
| 文件与资料 | 白名单目录内的列目录、读、搜索、写入（先备份）、移动到回收区；网页搜索、网页读取（防 SSRF） | 白名单外一律拒绝；删除只会移到回收区 |
| 博客与开发 | 读写 `D:\MyBlog` 的草稿（`_posts` 下 `draft` 状态）；`hexo generate` 和本地预览；`git status / diff`；根据 `implementation_status.md` 生成开发日志草稿 | 发布、`git push`、`hexo deploy` 每次都要确认 |
| 操作电脑 | 截屏后交给多模态模型理解，然后点击、输入、按键、切换窗口 | 默认关闭；按应用设白名单；你一动鼠标或键盘就暂停；按说话键可以打断；涉及金钱、密码、发送消息的步骤一律交还给你操作 |
| QQ | 连接你自行安装的 OneBot v11 实现（如 NapCat）；查看状态、读群历史、回复、私聊、发表情包或语音条；运行模式有旁观、被叫才说、模拟群友 | 群和好友都要进白名单；发送后回读确认；建议使用小号 |
| B站 | 使用你提供的登录 Cookie；看视频、打分、收藏，评论或回帖，发动态；每天有额度 | 评论和发动态默认需要确认；遵守频率上限 |

## 8. 用量与额度（usage）

- 请求时要求接口返回用量（`stream_options.include_usage`），按用途分类记录：陪伴、agent、记忆整理、目的机制、QQ、B站、语音。
- 价目表可配置，单位为人民币元每百万词元。
- 设每日额度：可以只设总额，也可以分类设。用到 80% 时由角色提醒，用到 100% 时该类别停止，只保留本地台词。
- 看板放在聊天面板的"用量"页：今日、7 日趋势、按用途分项、单次最贵的对话轮次。

## 9. 风险与边界

| 风险 | 处理 |
| --- | --- |
| 自研骨骼渲染器工作量大 | P1 先只做 rot + warp + 弹簧，达到大肥鱼的基本效果再扩展；保留 v2 立绘渲染器作为后备 |
| WebEngine 内存 | P1 实测；预算为常驻不超过 350 MB，否则评估 QML |
| 第三方贴图版权 | 大肥鱼只在本机导入，不提交、不分发；博客截图署名；尽早换成自己的形象 |
| QQ / B站 账号风险 | 不替你登录、不绕过风控；建议用小号；严格频率上限；QQ 运行时由你自行安装；遵守平台条款 |
| 操作电脑误操作 | 默认关闭，按应用白名单，你一动就停，敏感步骤交还给你 |
| 外放回声 | 两种方案实测后再定；实在不行时，外放模式改用按住说话 |
| 词元超支 | 闲聊不带工具表；分类额度；80% 提醒、100% 停止 |
| 工程量 | 每阶段独立验收，博客按阶段写，不把计划写成已完成 |
