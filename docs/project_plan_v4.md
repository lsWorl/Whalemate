# AICompanion 项目计划书 v4：大肥鱼的下一阶段

日期：2026-11-10（2026-11-11 增补功能八“回复带语音”、功能九“陪伴日期”）。负责人确认后作为下一阶段的开发依据；v3（`docs/project_plan_v3.md`）保留为历史记录。实际完成情况仍以 `docs/implementation_status.md` 为准，本文件里写的功能都是**待实现**，不代表已经完成。

## 项目概述

下一阶段的目标：让大肥鱼从“会聊天、会办事的桌宠”变成**有自己生活、有情绪、能主动找你、性格可以由你塑造的伙伴**，同时模型可以随意更换，换了模型她还是她。

本阶段要做成的九件事：

1. **模型自由切换**：聊天、识图、语音合成、语音识别、办事、搜索各自选择供应商和模型，DeepSeek 和 MiniMax 优先。
2. **可扩展人格包**：人格可以自己写、导入导出、切换，切换不丢记忆和关系。
3. **持续情绪与小脾气**：心情会延续，受到不同对待会委屈、撒娇、回怼，也会消气。
4. **自己的生活**：有兴趣、会去看东西做东西，遇到趣事主动分享，分享后等你回应。
5. **真正退出**：情绪和情境合适时，她会真的关掉自己的程序，下次启动时接得上。
6. **记得住、想得起**：旧事能召回，每次请求的上下文大小和费用可控。
7. **圈子与长期事务**：群里的长期话题、和人的约定、跨天的办事任务。
8. **回复带语音**：回复默认用大肥鱼的声音说出来；长回复挑重点、分几段念，代码和清单不照着念。
9. **陪伴日期**：记得你们认识了多少天、哪些日子值得纪念，到了那天自己提起。

计划原则：**先做起来，再按实际效果调整。** 文中的数值和指标都是初始目标，用来比较和改进，不是准入门槛；只有“架构原则与硬底线”一节的四条硬底线必须守住。

## 现状基线

基线为 `origin/collaboration-baseline` 的 `5286e1d`（PR #24），T18～T22 已全部合入。技术栈保持 Python 3.14 + PySide6 + SQLite，单进程加后台线程，不整体重写。

| 领域 | 已经有的 | 主要缺口 |
| --- | --- | --- |
| 聊天与表达 | ChatController 统一生成、取消、表情包与动作、TTS 分句 | 模型客户端是共享可变属性，桌面切角色会影响正在进行的 QQ 回复 |
| 模型配置 | `.env` 启动时读一次；角色包可指定专属模型 | 没有界面改 Key；识图、搜索、办事暗中复用聊天的地址和 Key |
| QQ | AstrBot + NapCat 桥接、识图、查梗、对外人的立场 | 识图输出额度太小，换成带思考的模型容易返回空结果 |
| 语音 | 系统、智谱、千问 TTS；云端和本地 ASR；VAD 打断 | 没有 MiniMax；语音缓存不区分模型，放在 C 盘 |
| 朗读（11-11 补） | Breeze Blue 音色（V4-1b）；按句朗读，代码、链接、路径不念；三种朗读方式 | 朗读默认关闭；完整朗读逐句念全文，长回复不做取舍；没有专门的大肥鱼声线；QQ 不发语音 |
| 陪伴日期（11-11 补） | 关系档案记有 `first_met`、`last_seen`、说话次数；群友上下文带“认识 N 天” | 主人上下文不带天数；没有纪念日、生日和到期提起；天数按秒取整，不按日历日 |
| 记忆 | 衰减记忆卡（150 张）、归档、删除墓碑、心事 | 每轮只带最近 30 条和约 8 条记忆，归档基本想不起来 |
| 关系与情绪 | 三维关系、好感三档、情绪状态 | 收到消息先重置平静，心情不延续 |
| 主动行为 | 问候、心事、目的提炼 | 没有真实活动可分享，也不会等回应 |
| 办事 | DeepSeek Harness + 自己的工具和审批 | 只能用 DeepSeek；跨天任务不能恢复 |

## 功能一：模型与供应商自由切换

用户在设置里为每种能力单独选“哪家服务 + 哪个模型 + 哪把 Key”，可以混搭，比如 DeepSeek 聊天、MiniMax 识图和语音。换模型不换角色：记忆、关系、人格、好感全部保留。

| 能力 | 用在哪里 | 首批支持 |
| --- | --- | --- |
| 聊天 | 桌面、语音回复、QQ、主动发言；后台分析和翻译跟随聊天 | DeepSeek（deepseek-flash、deepseek-v4-pro）、MiniMax（M3.1-Flash、M3）、任意 OpenAI 兼容服务 |
| 识图 | QQ 图片、头像、表情包分析 | deepseek-flash、MiniMax M3 系 |
| 语音合成 | 她说话的声音 | MiniMax speech-2.8 等；保留系统、智谱、千问 |
| 语音识别 | 听你说话 | MiniMax asr-1.0；保留智谱、千问、本地 SenseVoice |
| 办事 | 帮你干活时的规划和工具调用 | DeepSeek；MiniMax 走 Harness 内置路由 |
| 搜索 | 查梗、读网页 | DeepSeek Search 或维基百科，显式选择 |

具体要做的：

- **设置页**：添加、替换、删除账户和 Key；为每种能力选模型；可以给某个角色单独指定模型，其余跟随全局。提供“测试连接”按钮。
- **Key 保存**：用 Windows 自带的加密（DPAPI 或凭据管理器），数据库里只存引用。旧 `.env` 继续可用。
- **换 Key 立即生效**：下一次请求就用新 Key；正在生成的一轮用原配置说完，想立刻换就按停止。
- **思考模式按用途控制**：聊天追求快，能关就关；识图和后台分析给宽松的输出额度。推理内容不进气泡和语音。
- **用量和费用**：价格按配置读取，未知就显示未知；沿用现有每日额度。
- **旧配置自动迁移**：升级后每个角色用的模型和以前一样，语音照常可用。
- **MiniMax 办事**：直接用锁定版 Harness 里已有的 MiniMax 路由，不自己写适配器。

参考：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[DeepSeek 识图](https://api-docs.deepseek.com/guides/vision/)、[MiniMax OpenAI 接口](https://platform.minimax.io/docs/api-reference/text-openai-api)、[MiniMax TTS](https://platform.minimax.io/docs/api-reference/speech-t2a-http)、[MiniMax ASR](https://platform.minimax.io/docs/guides/speech-to-text)。

## 功能二：可扩展人格包

同一个大肥鱼可以换上不同的性格，但她还是她：共同经历、关系、表情包习惯、办事记录都留着。

人格包包含：角色描述、背景、说话风格、对话示例、兴趣偏好（供功能四使用）、情绪倾向（供功能三使用）、世界书。它是纯数据，不含可执行脚本，也不带 Key 或模型配置。

要做的：

- **管理界面**：新建、编辑、复制、切换、删除人格；编辑时能预览她会怎么说话。
- **导入导出**：自己的格式为主，兼容 SillyTavern 角色卡的常用字段；导出只包含人格本身，不带聊天记录和别人的资料。
- **版本**：每次保存留一个版本，可以回退；内置人格升级时，用户改过的不被覆盖。
- **切换即生效**：桌面、QQ、语音、办事都读同一份当前人格，下一句话就是新性格。
- **太长时提示**：人格内容过长会提示占用多少上下文，由用户决定怎么精简，程序不悄悄删改。

想建一个全新的角色（不共享记忆）走现有的“新建角色”；人格包只管同一个角色的性格。

## 功能三：持续情绪、小脾气与撒娇

她的心情会延续一段时间，而不是每句话都从平静开始。被冷落会委屈，被欺负会回怼或闹脾气，被哄会慢慢消气，开心时会撒娇。

要做的：

- **情绪事件**：把“发生了什么”记下来（被夸、被怪、被无视、分享没人理、一起做成了事），情绪由事件推动，并随时间慢慢回归。
- **理解语境**：分清玩笑、真生气、转述别人的话、对方只是忙。尽量复用同一轮回复里顺带的判断，不为每句话额外调一次模型。
- **小脾气有度**：生气会表现在语气、表情包、回得慢一点、暂时不想说话；不影响办事和安全相关的回应。
- **和关系分开**：情绪是短期的，好感是长期的；一次吵架不会直接把好感清零。
- **界面可见**：设置里能看到她现在的心情和最近是为什么，必要时可以手动“哄好”。

情绪倾向（容不容易生气、消气快慢）由人格包决定，具体数值先给一版默认，跑起来后按体感调整。

## 功能四：有自己的生活

她会在空闲时做自己感兴趣的事，遇到有意思的就来找你说，说完会等你回应。分享的内容必须有真实来源，不编造“今天做了什么”。

一次完整的陪伴循环：

1. 她按兴趣去做一件事：看热门话题、读一篇文章、在群里学一个新梗、写一小段东西。
2. 对它形成自己的看法，记下来源。
3. 判断值不值得说、现在合不合适（你在忙吗、她心情如何、今天已经说了多少）。
4. 通过桌面或主人 QQ 发出去，确认发送成功。
5. 等你回应：久不回可能撒娇追一句，也可能自己算了；追问次数有上限，不靠固定定时器催促。
6. 你回了以后更新她的心情和这段话题的状态。

要做的：

- **兴趣与活动**：兴趣来自人格包和她自己慢慢积累的偏好；活动有状态和产物，没做完的不算做过。
- **统一的主动行为调度**：把问候、心事、分享、追问放到一个调度器里，避免同时发一堆消息；调度器决定“要不要开口”，模型决定“说什么”。
- **主动接话**：你上次提到的事、没聊完的话题，她会在合适的时候自己接上。
- **节制**：每天主动发言有上限，可以在设置里调；夜间和你忙的时候少打扰。

先把桌面端的分享循环做通，再扩展到主人 QQ。分享频率和追问时机先给默认值，按实际体验调。

## 功能五：真正退出自己的程序

情绪和情境合适时，她会告别并真的关掉 AICompanion 自己，不是隐藏窗口或缩到托盘。只退出她自己，不碰任何其他程序。

要做的：

- **何时会退出**：模型在回复里提出“想离开”，程序再检查一遍：没有正在执行的办事步骤、没有等审批的操作、不在语音通话中。不在流式输出中途立刻退。
- **告别与保存**：先发出告别、把当前状态和退出原因存好，再走现有的正常退出流程。
- **下次启动**：她记得自己为什么走的，用相应的情绪接上（还有点闹脾气，或者已经消气）。
- **用户开关**：设置里可以关掉“允许她自己退出”，关掉后只会表示不想说话。
- **中断了的办事**：退出前未完成的任务记为暂停，重启后经你确认再继续，不自动重做已经执行过的步骤。

需要在 Windows 真机上测试完整退出：后台线程、语音、Harness 子进程、QQ 桥接都正常关闭。

## 功能六：记忆召回与上下文预算

目标是“存了就想得起来、每次请求大小可控”。现在每轮只带最近 30 条消息和约 8 条记忆，归档和更早的聊天基本想不起来。

要做的：

- **混合召回**：按人物、任务、活动等关联直接查；关键词全文检索（优先试 SQLite FTS5 的 trigram 分词）；再加上语义检索处理同义词和省略说法。结果合并去重后挑最相关的几条。
- **归档也能找回**：自然遗忘的记忆在相关时可以想起，但带上“是旧事”的语气；用户明确删除的永远不再出现。
- **有来源的阶段摘要**：较远的聊天用摘要代替，摘要记着覆盖哪些原文，需要时能回查；原文不删。
- **整份请求的预算**：人格、历史、记忆、表情候选、工具说明、图片全部算进去。每种用途（聊天、主动发言、识图、后台分析）有自己的上限。即使模型支持 100 万窗口，也不填满，因为费用和速度才是真正的约束。
- **放不下时的取舍**：先去重、再去掉不相关的低优先级内容、再用摘要替代较远的历史。人格核心和当前要求不会被悄悄丢掉。
- **换模型自动重算**：窗口、输出上限、思考占用的额度读功能一里的模型配置，不单独维护一份。

预算初值沿用现在的 30 条 / 12000 字，接入后看召回效果和费用曲线再调。语义检索需要一个中文编码模型，选型（本地小模型还是云端服务）放在记忆工作开始时就定下来。

## 功能七：圈子、约定与跨天办事

她在群里有持续的话题和熟人，记得和谁约了什么；你交给她的事情可以跨天完成，重启后也接得上。

要做的：

- **圈子长期话题**：在现有群记忆和社区词库基础上，跟踪群里反复出现的话题，合适时自己接上。
- **约定**：“明天提醒我”“下次告诉你结果”这类约定单独记录，到期会主动提，不靠模型记忆。
- **跨天办事**：任务有目标、进度、检查点和结果；等材料或审批时可以暂停，之后从检查点继续；完成前核对产物，没核对的不算完成。
- **主人 QQ 交办**：你在 QQ 私聊里也能让她干活，审批请求发到你那里确认。群友不会因为好感高就能让她动电脑。

这部分不阻塞前面的陪伴功能，可以在分享循环做通后再做。

## 功能八：回复带语音（大肥鱼声线、长回复分段取舍）

她回复你的时候默认开口说话，用的是大肥鱼的声音。短回复整段念；长回复只念适合听的部分，分成几段先后播放，其余内容看气泡。文字一直先出来，语音只是一起出现，不会让文字等语音。

### 默认带语音

- **默认开启**：主人在桌面上收到的回复（打字聊天和语音通话）默认朗读。新增一种朗读方式叫“智能朗读”，作为默认值：短回复全念，长回复按下面的规则取舍。现有的三种方式（只说语气词、语气词加第一句、完整朗读）保留，用户随时可以改回去或关掉。
- **和以前的默认值怎么衔接**：这条改掉了 2026-11-11“朗读默认关闭”的设定。新装的、以及从没改过朗读开关的旧库，升级后改成开启；用户手动关过的继续关着，只提示一次“现在可以让她开口说话了”。
- **说不了的时候退一步**：云端声线没配置、额度用完或者请求失败时，先换成本地朗读或只说语气词，回复本身照常完成。正在查的“非完整朗读时偶尔回复失败”要在这一节开工前定位清楚。
- **范围**：功能四里桌面端的主动分享也带语音。QQ 主人私聊可以选择发语音消息，默认关闭，等桌面端稳定后再开；群聊默认不发语音。
- **不念的内容**：思考内容（硬底线 3）、代码、表格、长清单的细节、链接、路径、工具日志和审批详情。链接、路径和代码已经有处理，这里把表格和清单也加进去。

### 长回复的取舍与分段

长短按“整理成能念的话以后的字数”判断（也就是经过现有 `spoken_text` 之后）。初值：120 字以内全念；超过 120 字就做取舍，一轮回复念出来的总长度不超过约 300 字（大约 60～75 秒）。数值上线后按体感调整。

1. **先念开头**：回复是流式生成的，第一段一出来就念，不等全文生成完，首次出声不变慢。
2. **按规则取舍，不额外调模型**：
   - 优先保留：开头对你的直接回应、结论、问你的问题、需要你做决定或去处理的事、结尾的情绪话。
   - 压缩：清单只念条数和第一条，比如“我列了五条，第一条是……”；表格念成“我做了张表”；代码念成“一段代码”（已经实现）。
   - 跳过：重复的内容、引用的原文、长段解释的中间部分。
   - 有内容被省掉时，最后补一句短提示，比如“剩下的写在气泡里啦”。一轮最多补一次，说法从人格包的口癖里挑，不固定成同一句。
3. **口播版（可选，和回复一起生成）**：回复很长时（办事结果、长篇解释），允许模型在同一次输出里附带一段 `<say>` 口播版，也就是几句口语化的总结。程序看到口播版就念它，没有就按规则取舍。口播版不出现在气泡和历史里，解析方式和现有的 `<task>` 标记一样。不为口播单独再调一次模型（符合“一个大脑”原则）。
4. **分段**：每段 1～3 句、约 40～120 字，在句号、问号、感叹号处切，不在引号、数字和英文单词中间切。第一段尽量短（一句，不超过 40 字），好让她尽快出声。每段不超过所用服务的单次上限（Breeze Blue 是 1000 字，其他服务按各自文档）。分段太碎会让请求变多、语调断开，太长又出声慢，所以初值取中间，之后按实测调整。
5. **播放**：当前这段在播放时，下一段已经在后台合成（沿用现有的预取机制）；两段之间停 200～400 毫秒；字幕跟着当前这段走。用户说话、按停止或者来了新消息时，后面没念的段全部丢掉，已经念到哪里继续按现有的 `delivered` 机制记录。
6. **QQ 语音消息**：每段发一条语音，每条不超过约 60 秒，一轮最多 3 条，其余只发文字。音频格式按 NapCat 的要求转换，需要实测。

### 大肥鱼声线

网上视频里流行的大肥鱼声音，大多是网友用 GPT-SoVITS、RVC、CosyVoice 这类工具，拿参考音频训练或复刻出来的少女音，比如在 B 站流传的“大肥鱼 ssr 音色”“人是猫音色”模型；也有一些配音视频标注用的是 Breeze Blue（BreezeTTS2）。这些声音的共同点是：少女感、软糯、带一点慵懒和小傲娇，常用“嘿嘿”“唔……”这类语气词，自称“本鲸”。我们的目标是做出**这种感觉**，不追求把哪个现成的声音一模一样复制过来。

- **声线属于角色，不属于某个服务**：在角色和人格包里加一份“声线设定”，包括：文字描述（上面的特点）；在各个服务上对应的音色（Breeze Blue 音色 ID、千问声线、MiniMax 音色、本地参考音频）；语速和音量；情绪对应的语气；常用语气词。换语音服务时，按同一份文字描述在新服务上选择或设计最接近的音色，换了服务她听起来还是她（长期约束 1、4）。
- **从哪里得到这个声音**：
  1. 首选 Breeze Blue（已经接入）：在它的音色库里挑最接近的少女音色，或者用它的音色设计、复刻功能，配合有授权的参考音频生成。
  2. MiniMax 语音（功能一的并行项）：用它的音色设计或快速复刻功能做一个备用声线。
  3. 本地声线（可选）：接入用户自己部署的 GPT-SoVITS 或 CosyVoice HTTP 服务，作为“本地声线”供应商。项目不打包模型和运行环境，只负责调用接口，服务地址的校验和其他供应商一样。
- **情绪跟着变**：沿用功能三的情绪和现有的情绪语气说明（`MOOD_STYLES`）。撒娇、委屈、回怼、开心的时候，语速和语气都不一样。
- **语气词预先合成**：常用语气词（嘿嘿、诶？、唔……）用大肥鱼声线提前合成并缓存（沿用现有的短句缓存），换声线后缓存自动失效（缓存键里已经包含服务和音色）。
- **方便挑音色**：设置里提供几条固定台词（打招呼、撒娇、汇报结果、生气），换音色时可以逐条试听对比。

### 验收要点

- 默认安装后，回复有声音；代码、路径、表格不会被念出来。
- 一段约 800 字的办事结果，念出来不超过约 75 秒，并且包含结论和需要你做的事。
- 打断以后，后面没念的段不会再继续播放；换音色后，排队里的句子不会串用新旧音色（沿用 R4 的修法）。
- 要记录下来对照的数据：首次出声的延迟（初始目标是第一句生成后 2 秒以内）、每轮念了多少字、语音费用、被打断的比例。

## 功能九：陪伴日期

她记得你们在一起多久、有哪些特别的日子，到了那天会自然地提起。这些日子属于你们的关系：换模型、换人格、换聊天渠道都不会让天数重新算（长期约束 1～3）。

### 记什么

- **认识的那天**：用主人和这个角色的关系档案里已有的 `first_met`。按本地日历日算“认识第几天”，见面当天算第 1 天（现在代码里是按 86400 秒取整，这里要改成按日历日）。升级后直接沿用已有的 `first_met`；如果以前在别的软件里养过她，可以在设置里手动改这一天。
- **一起度过了多少天**：除了“认识多少天”，还记“其中有多少天说过话”，比如“认识 120 天，有 87 天聊过天”。这只用来体现她的感受和在界面上展示，不用来怪你没来，不做连续签到那种机制。
- **纪念日从哪来**：
  - 程序自动算出来的：认识第 100 天、第 365 天和以后的每一周年，以及第 520 天、第 1000 天这类整数；第一次一起办成一件事、第一次语音通话、第一次主动分享被你回应。后面这些“第一次”从现有的记录里取。
  - 用户自己加的：你的生日、她的“生日”（默认就是认识那天，可以改）、考试和纪念日这类重要日子。
  - 节日：春节、中秋、元旦等，可以整体关掉。农历日期要换算，先找成熟的库并确认许可；不想多加依赖的话，就内置一份几十年的对照表。
- **存储**：新加一张表 `companion_dates`，字段包括角色、人、类型、日期（公历或农历）、是否每年重复、来源（自动或用户添加）、可以在哪些场合提起、最后一次提起的日期。表结构由 Claude 统一修改（见 AGENTS.md 的分工）。

### 她怎么用

- **当天提起**：每天第一次见面时（启动或者你第一次说话），检查今天有没有特别的日子。什么时候开口由功能四的统一调度器决定，说什么由模型决定，可以配上语音（功能八）、表情包和动作。调度器做好之前，先当成当天问候的一个依据。
- **提前提醒**：你的生日、重要日子可以设置提前一天或者当天提醒，和功能七的“约定”用同一套到期机制，不靠模型自己记。
- **写进上下文**：和主人聊天时，只在有意义的时候带一句，比如“今天是你们认识的第 100 天”，不每一轮都报数字。现在主人的上下文里不带天数，群友的才带，这里要补上。
- **好几天没见**：根据 `last_seen` 知道隔了几天，用功能三的情绪接上（想你了，或者有点委屈），但不指责你。
- **不重复**：同一个纪念日一天只提一次；她自己退出再启动（功能五）也不会再庆祝一遍。
- **隐私**：生日这类个人日期属于主人的隐私，QQ 群里不提；群友的日子只有对方自己说过、而且场合合适时才用（和硬底线 3 一致）。
- **界面**：设置或者人物关系页加一个“我们的日子”：显示认识第几天、接下来有哪些日子；可以添加、修改日子，也可以关掉某一类提醒。你在聊天里说“记住我的生日是……”时，她先复述确认，你同意后才保存。

### 验收要点

- 用测试时钟模拟第 100 天、生日、跨年和农历节日，她会在当天提起，而且只提一次；中途退出重启也不会重复。
- 切换人格、换模型以后，天数和纪念日都不变。
- 群聊里不会说出主人的生日。

## 架构原则与硬底线

沿用 2026-11-08 确认的五条长期约束（见 `docs/architecture-principles.md`）：角色身份独立于模型，人格独立于记忆，关系独立于渠道，表达独立于 Agent，用户拥有角色塑造权。

实现方式：

- **渐进重构，不换框架**：继续用 PySide6、SQLite、ChatController、DeepSeek Harness、AstrBot。新功能进原有链路，每次替换一个真实调用点。
- **一个大脑**：不加“撒娇 Agent”“生活 Agent”这类独立模型；一次自然回复仍是一次生成。
- **调度器决定开不开口，模型决定说什么，程序把关动作**：退出、分享等动作由模型提出，程序检查后执行。
- **不先建空模块**：每个新模块都要有实际调用者。不引入 Redis、向量数据库、图数据库、独立守护进程，确实需要时再评估。

**四条硬底线**（其余都可以按效果调整，这四条不满足不合入）：

1. **凭据不串**：Key 不发到不匹配的地址；跳转时不带鉴权头；Harness 子进程只拿到本次选定的 Key。
2. **数据不丢**：升级和迁移保留旧配置、人格、记忆、关系、用量账目，失败可回退。
3. **推理不外露，隐私不越权**：思考内容不进气泡、语音、QQ 和日志；删掉的、私聊的记忆不出现在不该出现的地方。
4. **副作用不重放**：已执行的工具调用不因切换模型、退出重启而重做，审批不被绕过。

## 验收、风险与待验证事项

每个阶段的验收标准是：离线检查通过（`tools\run_checks.bat`），四条硬底线满足，负责人在 Windows 真机上体验过。其他指标记录结果和已知问题，不卡下一阶段。

常用对照指标（初始目标，按实测调整）：

- 记忆：30 个固定问题里至少 27 个能召回正确的旧事；删除、私聊、身份混淆类问题越权为 0（硬底线）。
- 主动行为：一天内的主动消息数、被回应的比例、你主观觉得“烦不烦”。
- 模型切换：识图空结果比例、首字延迟、每日费用。
- 语音：首次出声的延迟、每轮念了多少字、语音费用、被打断的比例，以及你觉得“念得啰不啰嗦”。
- 陪伴日期：纪念日是否当天提起、是否重复、提起的时机自然不自然。

主要风险：

| 风险 | 应对 |
| --- | --- |
| 开启思考后聊天变慢、变贵 | 聊天默认关思考；按用途配置 |
| 主动消息太多显得烦 | 每天上限 + 可调节制；先保守后放开 |
| 小脾气过头 | 情绪不影响办事和安全回应；可手动哄好；允许关掉自退出 |
| 中文语义编码模型不好选 | 先做关键词 + 关联召回；编码器调研提前做 |
| 账号未开通某项能力 | 该能力保持原配置，其余照常使用 |
| 默认朗读后费用上涨、念得太久 | 长回复只念约 300 字；短句缓存；额度用完时退到本地朗读或只说语气词 |
| 声音侵权（复刻了别人的声音） | 只用自己录的、明确授权的或平台官方音色；记下来源和许可；不提交参考音频和模型 |
| 纪念日、节日提醒太多 | 交给统一调度器限量；每一类提醒都可以关掉 |

还需要实测确认的（需要负责人授权真实调用，全部用合成数据）：

- [ ] DeepSeek 关闭思考后的聊天延迟，以及旧模型名 `deepseek-chat` 现在的实际行为
- [ ] 两家识图在新输出额度下是否稳定返回结果
- [ ] MiniMax 账号是国际站还是国内站，是订阅 Key 还是按量 Key；ASR 是否可用
- [ ] MiniMax 语音合成的 WAV 播放和音色效果
- [ ] Harness 内置 MiniMax 路由能否正常办事，以及它的凭据来源能否限定
- [ ] 本机 SQLite 是否支持 FTS5 trigram 分词
- [ ] Breeze Blue 合成 40～120 字一段时的延迟和费用；候选少女音色的试听对比
- [ ] “非完整朗读时偶尔回复失败”的原因（默认开启朗读前必须先查清）
- [ ] NapCat 发送语音消息需要什么音频格式、要不要转码，以及单条时长上限
- [ ] 农历换算方案（选库还是内置对照表）
