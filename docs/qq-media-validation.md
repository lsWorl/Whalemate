# QQ 识图和表情包验收

## 准备

更新代码后，从托盘彻底退出桌宠，再运行 `main.py`。自动管理模式会同步安装 v0.4 插件并重启组件；接入外部 AstrBot 时，需要在其管理页重载桌宠插件。

在“设置 → 聊天平台”确认“已连接”，填写自己的 QQ 号、勾选允许的群；打开“看懂收到的图片”和“聊天时可以发表情包”，点保存。识图要求当前角色使用 DeepSeek 官方 API；高级设置的识图模型默认 `deepseek-flash`。不需要另填一套密钥，原聊天模型保持原设置。

默认表情是仓库自带的原创鲸娘。使用其他图库时，在“表情图库”选择包含 `manifest.json` 和 `memes/` 的社区基础包，或按分类放图的普通目录：

```text
我的图库/
  happy/开心.png
  sleepy/晚安.gif
```

使用自己有权发送的素材。支持 PNG / JPEG / GIF / WebP；一次最多发送一张，默认同一会话间隔至少 60 秒（高级设置可调）。清空目录输入框并保存即可恢复自带图库。

## 功能检查

### 发图后只收到文字提示

先复制诊断信息，检查 `AstrBot 桥接插件`。这是最近一次心跳报告的**实际运行版本**，不是磁盘上的插件文件版本；识图版本应为 `plugin-0.5.1`（或后续版本），心跳不能已过期。

本次私聊故障已定位：安装目录仍是 v0.3.0，没有图片转发函数，只把 `[图片]` 等文字提示交给桌宠。更新项目代码后，需在“聊天平台”停止并重新启动 QQ 服务，或在 AstrBot 面板重载桌宠桥接插件；只重开设置页不会重载插件。手动接入的实例应先更新插件文件再重载。等待最多 15 秒，再私聊发送原表情包验证。

NapCat 按 `image` 消息段上报 QQ 商城表情包，沿用 AstrBot 图片转换；GIF / WebP 动图首版识别首帧，不读取完整动作。参考：[NapCat 官方消息兼容表](https://napneko.github.io/develop/msg)。

### 收发检查

1. **纯图片**：用自己的 QQ 私聊机器人，只发一张内容清晰的图片，检查回复是否与图片有关。
2. **图文**：发送截图并问“这张图写了什么？”，检查数字 / 文字能否准确识别。一次最多 3 张；图片会压缩到最长边 1600，动图识别首帧。
3. **表情**：说“好开心，配一张开心表情”，检查收到图片或文字配图片。再说“只发一张开心表情”，间隔超过冷却后检查纯表情回复。
4. **允许的群**：勾选测试群并保存，在群里 @ 机器人并附图片。确认识图正常，且不提桌面私聊的原始记录、摘要或已标为 private 的记忆。
5. **权限**：未勾选的群或未授权的陌生人不应触发识图 / 回复。默认不回复陌生人私聊。
6. **关闭识图**：关掉识图并保存，等一次插件心跳（最多 15 秒）再发图，应说明图片尚未识别，不能编造看到了什么。关掉表情开关后只发文字。
7. **错误恢复**：在不改 API 密钥的情况下断网后发图，检查提示不能识图且不泄露接口或图片传输数据；恢复网络后重试。

群里没有叫她的图片不自动识图，避免刷屏时反复上传和产生费用。QQ、桌面共享的是原桌宠的人格与记忆；原图只用于当前请求，历史保存视觉描述。

## 自然聊天、头像和社区语境（v0.5）

日常分享“今天运气真好”“笑死，差点翻车”时，她可以自行配表情，不必要求“发表情”；有冷却，不保证每次配图。严肃问题仍应认真回答。允许群里的收尾 / 重复闲聊可不回复，实际效果需要在群里试。

打开“聊天习惯与社区”：

- “认识对话者的头像”默认开启。私聊问“我的头像是什么”，或在允许的群中 @ 某人并问“他的头像是什么”。首次查看会额外使用视觉接口，之后缓存一天；相同头像不重复识别。只看 QQ 公开头像图案，不当作真人外貌。新头像可以说“看看我的新头像”；网络失败时不能拿旧缓存冒充新头像。
- “从聊天和反馈中记住表达习惯”默认开启。短句、语气词等观察六条以上才总结；可以直接告诉她“你以后说话简短点”“不要总是追问我”“你聊天多配点表情”“不要发表情包”。偏好按人 / 会话隔离，不将群友习惯套到爹或另一个群。查看 / 清除入口会展示统计和有限偏好，不保存聊天原话；清除同时清掉头像印象。
- 按用户选择，新页面默认选“哔哩哔哩 / 动漫游戏”并勾选每天后台刷新，点保存后生效；已有社区选择不覆盖。也可改选“V2EX / 技术社区”。“现在逛逛社区”读取公开话题并显示来源 / 时间。后台刷新在聊天时发现过期背景后进行，不等待网络。勾选“本次社区选择只应用到上面勾选的群”，可以给不同群分别设社区。选择“日常闲聊”关闭热榜背景。

公开标题只作一天内的相关语境，她不会每条都播报热榜，也不应拿标题编造梗的完整含义。长期语气适配来自真实聊天和反馈，不是自动改人设或重新训练模型。头像和自然表情的真实 QQ 体验、玩梗是否合群仍需用户验收。

## 聊天卡与社区知识

用户已确认 v0.5.1 重载后私聊表情识别成功。按后续反馈，表情包只用于理解情绪和意思：自然接话或回表情，不向发图人分析画面、复述图中文字、讲解梗义和来源。普通截图的读字、排错等任务仍按提问处理。

“聊天习惯与社区”中的“使用聊天卡和社区知识”默认开启。鲸娘附带原创 ACG 群友聊天卡，用短对话示例说明如何接表情；身份和与爹的关系沿用角色页，其他用户不套用父女关系。示例不是历史，不作为真实经历保存。

“查看 / 导入聊天卡与世界书…”可以查看当前聊天卡、额外词义和已联网读取的社区知识。支持：

- 自定义 JSON：`name`、`style`、`samples`（user / assistant 对）及 `entries`（keys / content / source）。
- SillyTavern CCv2 JSON：读取 personality、mes_example（`{{user}}` / `{{char}}` 示例）和 character_book；不采用身份描述、system_prompt、post_history_instructions、工具和历史覆盖字段。PNG 卡请先从原工具导出 JSON。
- 独立世界书的 entries 列表或字典，支持 keys / key 与启用开关。按字面关键词检索，最多带入三条；支持 selective 的“任一主关键词且任一次关键词”，其他逻辑会明确报错，不执行正则、脚本、宏或递归。

导入后预览，点弹窗“保存”生效；“取消”保留原有选择，也可恢复内置卡和清空手动知识。最多 256 KiB、50 条知识，不联网获取卡片中的链接。卡片和手动知识按角色保存于现有设置存储，沿用记忆数据库选择的磁盘。

选择哔哩哔哩社区后，“现在逛逛社区”和自动后台刷新还会读取固定 BWIKI 原神黑话页的 MediaWiki API，摘录词名及首段释义，保存原页面来源。词义每周刷新，30 天后不再使用；热榜仍仅保留一天。现实中的“猫猫”等歧义词还要求出现游戏相关次关键词，避免把现实求助套进游戏语境。来源失败保留旧缓存，不上传聊天，不拿热榜猜词义。当前实测读到 8 条词义，来源限于该游戏社区，不能代表已掌握整个 B 站或全部动漫游戏文化；其他社区可导入合适的世界书补充。

参考的是 [SillyTavern 角色卡](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)与[世界书](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)的数据思路，以及 [AstrBot 人格接口](https://docs.astrbot.app/dev/star/guides/ai.html)。未复制第三方人格卡或插件代码；插件转发到桌宠大脑，因此聊天卡在桌宠一侧生效。
