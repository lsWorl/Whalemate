# T29 界面显示剩余额度

Codex 合并前复核补修：聊天顶部额度提示按可用宽度换行，避免在默认 420 像素窗口中截断账户余额。新增窄窗口、多账户的回归测试。

负责人 2026-11-16 要求在界面上显示用户还剩多少额度，并确认两种都要显示：

- **本地额度**：设置里“每日额度”还剩多少，按价目表估算。
- **服务商账户余额**：从服务商接口查询。

Claude 实现，Codex 审查。

## 改动

- **`usage/meter.Quota.remaining()`**
  - 返回设了上限的各项今日余量：上限、已用、剩余；`'*'` 表示总额。
  - 剩余不会低于 0。
- **`usage/balance.py`**：只查询官方提供余额接口的服务商，资料核对日期 2026-11-16。
  - DeepSeek：`GET https://api.deepseek.com/user/balance`，取人民币那一条的 `total_balance` 和 `is_available`。
  - Kimi（月之暗面）：`GET https://api.moonshot.cn/v1/users/me/balance`（或 `.ai`），取 `data.available_balance`。
  - MiniMax、智谱、百炼没有找到用 API Key 查余额的官方接口，不查询。自定义中转地址也不查，避免把 Key 发给别处。
  - 同一地址加同一凭据只查一次。单个服务商失败只显示简短原因（例如“Key 无效”），不含 Key 和地址。离线模式不联网。
  - 请求沿用 `net.open_url`，不跟随重定向。
- **`ui/quota_badge.py`**：一行小字，例如“今日额度剩 3.20 / 5.00 元 · DeepSeek 余额 12.34元”。没设额度时显示“今日已用约 x 元（未设额度）”。
  - 本地额度每 30 秒刷新，只在可见时刷新。
  - 账户余额在后台线程查询，10 分钟最多一次，点一下立即重查。
  - 退出时最多等待正在进行的查询结束（单个请求 5 秒超时）。
- **显示位置**：
  - 聊天面板顶部，名字和状态下面。
  - 设置的“用量”页顶部。

## Codex 第 1 轮审查后的修复

1. **自定义中转的 Key 被发到 DeepSeek 官方。** 原因是服务商种类为 DeepSeek 时会直接查官方接口，即使配置的地址是中转站。现在只按配置的地址判断：地址必须是 https 的官方域名才查询，种类不再起作用。
2. **国际站余额币种错误。** Kimi 国际站 `api.moonshot.ai` 返回的是美元，现在按美元显示；国内站 `api.moonshot.cn` 仍按人民币。
