# 群聊回复被截断、前后对不上（2026-11-11 真机记录修复）

负责：Claude 实现，Codex 审查。分支 `task/v4-qq-group-fix`，基于 `task/v4-3-mood`（PR #38）。

## 现象（负责人授权查看本机库里 qq 群聊记录，只读）

- tangle 要深渊配队，她回了完整的两队，群里却只看到"行 / 换一套纳塔环境成熟队 / 上半：玛薇卡"，于是"那继续说配队啊，没说完呢"；
  第二次要"完整的"，只看到"行 / 这次给完整一套 / 而且八个角色不重复"，过了一会儿问"怎么不说话了"。
- 她的记录里却是整段回复（以为全说了），下一轮就接不上："刚在想你要的是哪一期深渊……发来我照着配"，跟上一条自相矛盾。

## 原因

1. `bridge/service.py` 按态度截条数（冷淡一条、不熟最多三条）时直接丢掉后面的段，不管后面是不是答案本身。
2. 和外人聊（casual）时一行里夹在中文之间的空格算断点，"上半：玛薇卡 茜特拉莉 希诺宁 班尼特"被拆成一个名字一条，条数暴涨，正好被上面截掉。
3. 截掉以后数据库里仍是完整回复，模型看到的历史和群里看到的不一样。
4.（未改，另记）这条回复用 MiniMax-M3.1-Flash 生成了 9759 个输出 Token（主要是推理，这个模型不能关思考），用了约 2.5 分钟，对方以为她不说话了。

## 改法

- `expression/segments.py`
  - `is_listing`：带"标签："开头、或者 4 个以上短词用空格隔开的一行是列举，整行一条，不按空格拆。
  - `fit_cap`：只截零碎话（被截掉的每条 ≤6 字、合计 ≤16 字，例如"快点""别磨叽"）；有内容的回答照她拆好的条数全发（负责人 15:39："特殊情况可以多发几条会话消息，不用通过逗号这种方式分隔"）。
  - 超过防刷屏条数（8）时多出来的并进最后一条，改用换行连接，不再用逗号硬连。插件 0.9.6 同步。
- `bridge/service.py`：正在吵架（她的 `<mind/>` 判断对方冲她来 attack / sarcasm，或者她还在气头上）不按态度截条数；
  真的截掉了零碎话时，把数据库里这条回复改成实际发出去的内容，历史和群里看到的一致。
- `bridge/stance.py`：冷淡 / 不熟的提示里加例外——认真请教时把答案说完整；吵起来要还嘴可以多发几条短的。

## 没改的

- 必须思考的模型在 QQ 里慢：可以在模型页给 QQ 换成能关思考的模型（例如 MiniMax-M3），或以后给 chat 用途设输出上限（但上限会把推理和正文一起截，需要先评估）。
- 桌面上问"有人在和你聊天么"时不知道群里正在聊——桌面与 QQ 的上下文边界是隐私设计，要改需另开任务讨论。
