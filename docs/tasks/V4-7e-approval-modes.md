# V4-7e 一键审批

Codex 实现，Claude 审查合并。与 [V4-7b](V4-7b-qq-tasks.md) 共用分支和 PR。桌面和 QQ 会看到同一批等待用户决定的操作。

## 操作方式

聊天输入栏可在开工前选择模式，进行中切换对后续操作生效。设置里的“干活”页可保存默认模式，并按实际工作区根查看、添加、修改、删除允许和拒绝规则、查看命中次数。

| 模式 | 程序在何时放行 |
| --- | --- |
| 每步确认 | 只读操作照旧执行。普通副作用逐项询问，已明确授权的规则可复用。 |
| 自动接受工作区改动 | 工作区和本次放开的文件夹可新建、写入、移动。命令按只读判断或显式规则处理。 |
| 放手做 | 在工作区改动的基础上，允许参数、路径和用途可由程序核对的单条命令。 |

可复用项目显示实际文件夹或命令前缀。桌面可选“同意这一次”“本次任务都同意这类”“以后都允许”“拒绝”。拒绝可填写原因，工具把原因返回 Harness。QQ 发送“同意 编号”“同意这类 编号”“以后都允许 编号”或“拒绝 编号 原因”。办事记录注明项目规则、任务规则、模式或只读判断。

待审批项有独立编号。桌面显示数量，“全部同意”先逐条列出当前可合并的操作及详情。QQ 的“同意全部”只作用于这个主人已经收到的同一次任务的可批量项目。新到的一项仍需另行处理。

## 权限边界

拒绝规则优先于任务规则、项目允许规则、只读判断及模式。文件夹规则匹配真实路径，移动检查两端。命令按程序和子命令辨认，核对整条命令与参数。命令连接、管道、重定向、命令替换和不能判明范围的操作均无可复用的许可。

密钥、应用数据库和凭据目录受工具保护。附件原件、越界写入、.git 内部、系统及用户目录的改动、删除和恢复后的副作用逐项确认或拒绝。删除经回收区。恢复先核对剩余事项，此后继续使用已有操作指纹，避免结果未知时重放。网络下载执行不会因模式或规则自动通过。

负责人在本次实现中确认，npm run build、python -m pytest 等会执行项目代码的入口逐次确认，仍识别命令前缀、支持项目拒绝规则。原因是本机 exFAT 无法用 Windows 低完整性令牌约束脚本的子进程。C 盘的系统和用户目录同样保持逐次确认。

Windows 验证使用临时文件、合成旧库和离线模型。单测覆盖三档模式、规则归一、拒绝优先、项目隔离、队列快照、审批按钮、拒绝理由、双端竞答、命中次数和审计；桌宠 smoke 操作可复用审批并通过模拟 QQ 回复结算。真实项目命令和真实平台收发待验收。
