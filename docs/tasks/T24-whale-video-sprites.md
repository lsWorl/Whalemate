# T24：鲸鲸视频生成序列帧（试点）

负责：Codex 出图、调用视频模型、做后期处理和接入；Claude 定规格、写提示词模板、逐帧审片　分支：沿用 `task/t23-q-whale-rig`（worktree `.worktrees/t23-q-whale-rig`）

负责人 2026-11-14 决定：鲸鲸的动画改为“视频生成序列帧”路线。T23 的骨骼方案已暂停（提交 `0a5c6f9`），保留作后备。

## 为什么换路线

- 负责人认为 T23 主图 A 的脸和自己的参考图 `art/deepseek-whale-q/references/blue-original.png`（负责人自己用 AI 生成，可以随项目公开）差别太大。骨骼方案要把脸拆成很多层，很难完全保留原图的画风。
- 负责人看过并认可流畅度的 Aboutme 大肥鱼，源头是 PC2005-cloud/dsh-pet，做法是：提示词 → 绿幕视频 → 透明动画。具体是用视频生成工具（例如豆包）每个动作出一段 10 秒视频，提示词按秒分段描述动作；绿幕 #00FF00，头顶约在画面高度 20%、脚底约在 85%；**每段视频都从标准的正面站姿开始，并回到同一个站姿结束**；再抠绿、统一尺寸，输出带透明通道的视频。
- 鲸鲸现在用的 `animation_view.py`（`AnimationAvatar`）已经能播放这种整帧图集：12 FPS、淡入淡出过渡、走动时按距离推进帧。**播放器不用改**，只需换上自己的素材包。

## 核心做法：锚点帧 + 首尾帧生成

1. 先定一张“锚点帧”：鲸鲸的正面待机站姿，画风和脸以 `blue-original.png` 为准，纯绿背景，按上面 dsh 的比例构图。
2. 每个动作都用视频模型的**首尾帧模式**生成：首帧和尾帧都用锚点帧，中间的动作由提示词描述。这样每段都能无缝循环，任意两个动作之间也能经过锚点帧衔接，不会跳。
3. 需要特定姿势的动作（挥手到最高点、坐下），可以把首尾帧拆成“锚点 → 关键姿势”和“关键姿势 → 锚点”两段。关键姿势用 image_gen 以锚点帧为输入，在编辑模式下生成。
4. 去掉每段的最后一帧（它和第一帧相同），避免循环时停顿。

## 步骤

### 0. 选视频模型（等硬件查询结果，由 Claude 和负责人决定）

| 方式 | 条件 | 说明 |
| --- | --- | --- |
| 本地 Wan 2.2 首尾帧（ComfyUI） | 有 N 卡，显存足够 | 开源，Apache 2.0；5B 版本约 8 GB 显存可以跑 480p，14B 版本需要 24 GB 以上 |
| 云端 Wan 2.2 首尾帧 API | 无硬件要求 | 按次计费，单次约 0.23 美元级别 |
| 豆包 Seedance 等商业模型 | API 或网页 | dsh-pet 用的就是豆包；按秒计费，价格更高，使用前要核对平台的使用条款 |

API 密钥只放在本机环境变量里，不写进仓库，也不写进日志。

**本机评估结果（2026-11-14，Codex 实测）**：RTX 5070，12 GB 显存，驱动 610.88；内存 16 GB；本机没有装 ComfyUI；ffmpeg 9.0.2 支持 libvpx-vp9；有 Python 3.12。

**结论**：
- 能真正做首尾帧的是 Wan 2.2 的 14B 系列（FLF2V、Fun InP），量化后也要 20 GB 以上显存，12 GB 显卡加 16 GB 内存跑不动。
- 5B 版本能在 12 GB 上跑，但只支持首帧，不能保证回到锚点帧，循环接缝没有保证。
- 所以**试点用云端 API**：首选云端 Wan 2.2 14B 首尾帧（开源模型，许可清楚，单次费用低）；如果画质不够，再试豆包 Seedance 的首尾帧模式（dsh-pet 用的就是豆包）。
- 本地 5B 只用于不需要回到锚点的草稿，暂时不搭。
- 平台账号和 API 密钥由负责人自己申请，放进本机环境变量后告诉 Codex 变量名。


### 1. 锚点帧（负责人拍板）

- 用 image_gen，以 `blue-original.png` 为输入，出 3 张候选：正面待机站姿，双手自然下垂，双脚着地。纯 #00FF00 背景，16:9 画布，头顶约在 20% 高度、脚底约在 85%。保持参考图的大头 Q 版比例、粗描边、大眼睛和配色。
- 同时输出 300 px 高的缩略图，放在 `art/deepseek-whale-video/anchor/`；提示词记录到 `prompts.json`。
- 负责人选定 1 张后再进入下一步。

### 2. 试点：4 个动作

| 动作 | 时长 | 要点 |
| --- | --- | --- |
| idle 待机 | 4 秒循环 | 呼吸、眨眼一次、头发和尾巴轻微摆动；身体位置不变 |
| talk 说话 | 4 秒循环 | 嘴巴开合，头轻轻点，手可以有小动作 |
| happy 开心 / 挥手 | 3–4 秒 | 要有预备动作和回弹，最后回到锚点帧 |
| walk 原地走 | 2–3 秒循环 | 原地踏步，Q 版短腿交替，身体每步颠一下；横向移动交给程序 |

提示词模板由 Claude 提供，按秒分段，并固定以下约束：镜头不动，纯绿背景，没有阴影和地面，不出现文字或水印，角色不出画，首尾都是锚点姿势。

### 3. 后期处理（Codex 写脚本，放在 `tools/video_pet/`）

1. 抠绿：HSV 色相抠图，并去除边缘的绿色溢色；验收标准与 T23 第 2 轮相同（偏绿像素为 0，白底和深底上都看不出绿边）。
2. 防抖：只修正整体漂移，以第 1 帧为基准对齐脚底和中线；**不逐帧对齐包围盒**，否则会把动作本身也抹掉。
3. 循环：去掉最后一帧；首帧和末帧的差异要写进报告。
4. 打包：按 `animation_view.py` 现有的图集格式和 `animations.json` 字段输出（帧率、尺寸与 Aboutme 包一致，或者在报告里说明为什么不一致）。输出到 `output/t24-pack/`，**不替换默认形象**。
5. 预览：每个动作生成 GIF 和逐帧对比图；首帧与末帧并排；从锚点帧里抽取 8 帧，排成一张脸部一致性拼图。

### 4. 审片与验收

- Claude 逐个动作审片：脸和发型是否跑样（对照锚点帧）、循环接缝、绿边、闪烁、脚底打滑、身体或配饰凭空出现或消失。
- 用临时的角色目录启动桌宠，加载 `output/t24-pack/`，和 Aboutme 的对应动作并排录屏。不改 `ui/main_window.py` 的默认形象来源顺序。
- 负责人在真机上看过，认为脸像参考图、动作流畅度不低于 Aboutme，试点才算通过。之后再另开任务补全其余动作（思考、干活、庆祝、出错、犯困、被拎起、被戳、生气、害羞……）并接入默认形象。
