# V4-7d 圈子长期话题

Codex 实现，Claude 审查。分支 `task/v4-7d-circle-topics` 从 #63 合并后的 `7a7d0a0` 拉出。

## 在哪里看

在「设置 → QQ 与社区 → 圈子长期话题」选择已允许的群，可以查看名称、摘要、热度、出现天数和最近出现时间。选中一行能查看主要参与者和带消息编号的原话。每个角色在每个群的主动接话开关默认关闭。开关只管主动开口，被叫到或正常接话时仍可参考本群话题。

## 整理与来源

- 复用桥接的后台记忆整理批次和同一次模型请求，在原有 `memories` 旁接收 `topics`。每项包含短名、一句话摘要及支持它的本群用户消息编号。整理时给出原群已有的话题名，方便沿用。程序核对出处并按角色、频道、规范化名称合并。群之间同名的话题分别计数。
- 没配模型、额度停止或模型结果无法解析时，从同一批群消息统计重复关键词，优先识别本群词库里见过的词、书名和标签。重复分析同一条来源不会加热。已删除过记忆的角色只用删除边界之后的消息做规则提取。
- SQLite v19 → v20 增加 `circle_topics`、`circle_evidence`、`circle_tombstones` 和索引。沿用启动时备份与事务迁移。参与者用该发送者在**本角色、本群**的首条消息编号作群内人物编号，话题表不保存 QQ 号、昵称或跨群关系编号。
- 删除一个话题或清空本群时，只移除话题和出处引用，原消息保留。以本群当时的最新消息编号记删除边界，旧消息不能因模型换个标题而复活。其他已保存的话题仍可查看和使用，日后出现的新讨论可以重新形成话题。写入时复查边界，删除期间正在生成的旧批次作废。
- 普通群回复最多带本群热度前三的话题。热度按本地自然日计算，每天最多计三条来源，七天衰减一半。整份请求超出软预算时，先撤下这段背景。桌面和私聊不载入话题表，桌面原有的群动态也会跳过圈子主动发言和已移出允许列表的群。

## 主动接话与投递

统一调度器使用 `source='circle'`。启用的群最近七个自然日至少有两天谈到同一话题，且最近 30 分钟没人说话、她也没有刚在群里发言，才成为候选。有多个候选群时从热度高的开始。公开回复额度、插话额度、群插话档位、冷却、消息条数和概率沿用桥接规则，所有会话均遵守总开关、专注模式和安静时段。

每个角色在每个 QQ 群每天最多主动发送 2 条，两次至少间隔 90 分钟，同时只能有 1 条在途。圈子接话和该群到期的约定共用这份额度。主人桌面与绑定 QQ 私聊共用主人的每日上限、间隔和待回应记录。同一时刻都可发送时先处理主人；一个会话的消息只会结束该会话上一条消息的回应窗口。

调度器在占位时持久化目标会话。旧版记录根据圈子话题键、QQ 发件箱目标或约定的稳定 id 回填；确认失败释放本会话占位，重启时按原会话对账。

生成、出队和领取时核验群、开关和话题。她没有具体内容可以补充时可选择沉默，直到群里有新消息才会再考虑该话题。确定未发出的投递释放占位，已送达、部分送达及无法确认的投递保留防重记录。同一角色、群、话题一天最多接一次，跨午夜按实际首达日也防重。群里没人回时不追问、不记委屈。
