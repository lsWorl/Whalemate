# T17：收集表情包、向群友学发图习惯、聊天短句分条

负责人 2026-11-09 提出（Claude 实现，Codex 审计）：
1. 发图不要只靠写死的候选规则，要向社区学别人的发图习惯；
2. 保存聊天对方和群里的表情包；
3. 别人发的表情包能看懂含义，但不一定要回复；
4. 说话不用"，""。"分句，改成另起一段。

## 负责人的选择（2026-11-09）

| 问题 | 选择 |
| --- | --- |
| 学习来源 | 她所在的 QQ 群和私聊（本地学习，不上传聊天） |
| 收集的表情能不能直接发 | 分析后直接可用，任何地方（桌面、所有群、私聊） |
| 每天最多分析几张新表情 | 100 张（图库页可改） |
| 短句分条用在哪 | 桌面和 QQ 都用 |

## 实现

### 收集（`expression/collect.py`，插件 v0.8.0）

**插件端：**
- 识别表情包：
  - NapCat 图片段 `sub_type=1`，或摘要里写着"表情"（例如"[动画表情]"）；
  - 商城表情 `mface`：AstrBot 会把它丢掉，所以从原始消息段里读，只从 `gxh.vip.qq.com` / `i.gtimg.cn` 走 HTTPS 下载，不跟随跳转，1 MiB 以内。
- 传原图，GIF 动画保留，只认 GIF / PNG / JPEG / WebP 文件头。
- 每条消息最多 3 张。桌宠已经收过的图只传内容哈希。被叫到和旁听都收。普通照片旁听时仍然不读取。

**桌宠端：**
- 按内容哈希去重，写进用户图库的 `收集的表情/` 子目录。没有选择图库时不收集，不往仓库目录写。
- 许可记为 `qq-collected`。来源只记"QQ 群 / 私聊"和不可逆短哈希，不存号码、昵称、群号。
- 上限：总数 3000 张、每天新收 300 张；到上限只是不再收新图，不删旧图。

**分析：**
- 后台线程用识图模型分析一次，每张先预留当天额度。
- 输出：是不是表情包、适不适合发（色情、血腥、广告二维码、个人信息、聊天截图、政治敏感、羞辱真人都不适合）、含义、用法、情绪、图上文字。
- 不适合的自动停用；失败两次就不再重试；用户自己改过的标注不覆盖。
- 只有分析完、适合发的图才进候选。

**"看懂但不一定回复"：**
- 旁听时只发了表情包的消息：群聊记录写"[发了表情包：含义]"，她看懂、记下，但不插话。
- 私聊或被叫到时只发了表情包：她可以回图、回话，或只回【不说】（这一轮不发消息、不记回复）。
- 已经分析过的表情包直接用存好的含义，不再为它调用识图。

### 学习发图习惯（`expression/usage.py`）

- 别人每发一张表情包，记一条用法：发图前大家在说什么（情境，去掉说话人，截短到 60 字）→ 哪张图，加上会话的短哈希。环形保留 800 条，只存本机。
- 回复时把眼前几句话和这些情境按双字片段比相似度：
  - 相似度和常用程度加进候选排序；
  - 最多两个候选名额留给"和眼前最像的群友用法"；
  - 候选说明里写"群友在「…」时发过"，但只在学到它的同一个群里写原情境；别处只写"群友常用（N 次）"，不把一个群的聊天内容带到别的群或桌面。
- 没有额外的模型请求，也不设发图比例。

### 聊天短句分条（`expression/segments.py`，人设 v5）

- 不是文档类的回复，按下面的规则整理：
  - 每一行一条消息；
  - "。"处另起一条，连着的"。。。"换成"…"；
  - "，"换成空格；
  - 引号、书名号里的内容不拆；
  - 最多 6 条。
- 代码、列表、标题、引用、超过 600 字的长讲解照旧整条显示，保留标点。
- QQ 单条消息也换成整理后的写法。
- 数据库、模型历史、TTS 仍然是原文。
- 人设 v5 和场合提示改为"打字像发微信，不用逗号句号，一句一行"。v2～v4 原文自动升级，用户改过的人设不动。

### 顺手修的（来自负责人 11:13～11:20 的表达决策记录）

- 爹的 QQ 私聊在观测里显示成 `desktop`：改为按会话范围标成 `qq:user` / `qq:group`。
- `qq_cooldown`（发过图后 60 秒不给候选）只用于 QQ 群。实测爹在私聊里连着聊时，有 4 轮被挡；私聊和桌面一样，只避免 5 分钟内重复同一张。
- 模型照抄聊天记录里的 `<sticker sent="…"/>` 原来记成"图片编号 / 文件校验失败"，现在单独记为 `B_history_echo`。

## 第二轮（2026-11-09 12:31 之后）：Codex 审计 `7aaa065` + 负责人新要求

**Codex 审计**
- **[P1] 关闭 / 撤权后仍收图。** 解码校验放在锁外。落库、记用法改在 `RECORD_LOCK` 里，并按此刻设置重新 `classify`；`close()` 返回后不再有写入。后台分析每张开始前都检查服务是否已关闭、收集开关、识图开关和额度。回归：解码期间关闭服务（收图 0、记用法 0、分析 0）、撤掉群以后不再收、关掉收集后不分析。
- **[P2] 字符串 "false" 被当成适合。** `suitable` 必须是 JSON 布尔值，`sticker` 有的话也必须是布尔值；字符串、null、缺字段都按分析失败处理（两次后不再用）。回归覆盖这几种写法，以及走完整链路后不进候选。
- **[P2] 混合消息丢照片识别。** 插件附上对应关系：`image_parts`（每张图片来自第几个图片段）和 `sticker_parts`（每个表情包来自第几个图片段，商城表情记 -1）。桌宠只跳过"已看懂的那张表情包"对应的图片；旧插件没有对应关系时一张都不跳过。回归：商城表情加照片、图片表情加照片、无对应关系，以及插件端的字段。

**负责人新要求（参考开源 QQ 机器人，如 MaiBot：表情包默认都收，只按"公序良俗"这类宽松标准选择性过滤）**
- 分类放宽：识图说明默认 `suitable=true`，搞笑、可爱、中性、日常回应、吐槽、阴阳怪气都可以，只有明显不能发的才填 false。"是不是表情包"只记录、不拦（QQ 本来就标成表情包，存成表情的反应照片也算）。
- 中性表情能发：新增"回应"分组（收到、好的、嗯、看戏、围观、发呆、点赞……），每轮都有机会进候选。模型写的用法短语按包含关系归组。提示里写明中性、平常的图也能发。
- QQ 里聊技术也能配图：被问住、看到离谱的报错、讲完来一张都行，代码和步骤仍用文字写清楚。桌面上的"认真讲技术时用文字"不变。验收场景 `grp-tech` 改为发不发都合理。
- QQ 里不用什么都懂：QQ 私聊和群聊的场合提示都加上"问到不熟的，可以发一张可爱的表情包说自己不太懂，别硬答、别编"。
