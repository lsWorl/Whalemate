# T23：Q 版鲸鲸分层骨骼形象（试点）

负责：Codex 出图、写 RML 与接入；Claude 定规格、审图、定动作参数　分支：`task/t23-q-whale-rig`
负责人 2026-11-14 决定：鲸鲸的新默认形象采用 **Q 版 + 分层骨骼**，只用 Codex 内置 image_gen 与 Claude 配合完成，不使用视频生成模型。本文是试点范围；试点由负责人真机验收通过后，再决定是否替换 Aboutme 成为默认形象。

## 为什么换路线

- T20 自绘阶段让 image_gen 逐帧画中间姿势（86 张关键帧 + 光流、120 帧行走），每张都是独立生成，脸型、服装、腿部前后帧对不上，负责人否决。**本任务不再让模型画中间帧。**
- 骨骼方案每个部件只画一次，运行时由 `assets/rig/rig.js` 以 60 FPS 做旋转、网格弯曲和弹簧摆动。同一张贴图贯穿所有动作，不存在逐帧漂移；动作之间是参数过渡，没有整图叠化。
- 渲染器、动作引擎、`tools/rig_studio.py compile` 与 T6 第 2～4 节的分层规格都已经实现并有测试（`make_placeholder_pack.py` 占位包能走、甩、换表情）。之前没有走通，是因为当时的美术是从整张立绘事后抠层，被遮挡部位缺失。本任务按规格**从头为骨骼出图**。

## 技术选型（2026-11-14，负责人允许换语言、参考成熟方案）

动画层**首选 Rive**，现有 `rig.js` 留作后备。

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| **Rive**（CLI + RML + Web 运行时） | **首选** | 运行时 MIT 开源，没有授权费；位图可以加网格、绑骨骼，有自动权重和 IK；状态机支持动画分层与混合，动作切换由运行时负责；CLI 用纯文本 RML 生成 `.riv`，适合 Codex 编写；生成的文件能在 Rive 编辑器里手工微调 |
| 自研 `rig.js`（T6，Pixi 网格 + 弹簧） | 后备 | 已能运行，有测试；但混合、IK、关键帧编辑都要自己写和维护 |
| Spine | 不用 | 在应用里集成运行时需要持有 Spine 编辑器许可，与项目 MIT 公开冲突 |
| Inochi2D | 不用 | 只能在 Inochi Creator 图形界面里手工绑定，Codex 无法用文本编写；Creator 自 2024-09 的 0.8.6 之后没有新版本 |

接入方式：桌宠窗口本来就是 Qt WebEngine，`assets/rive/` 下放一个页面，加载本地打包的 Rive Web 运行时（WebGL2 或 Canvas 版，npm 包锁定版本、wasm 随包分发，**运行时不联网、不走 CDN**）。Python 端通过现有的 JS 桥只写状态机输入：`walk_speed`、`drag_vx`、`grabbed`、`mouth_open`、`expression`、`look_x/y`、`poke`、`pat` 等。表现逻辑全部放在 `.riv` 里。

`rig.js` 的弹簧效果（头发、耳鳍、尾巴余摆），在 Rive 中用状态机分层加 Luau 脚本或约束实现；第 4 步先验证能不能做到。

## 设计要求

- **画风**：Q 版，约 2.5 头身，大头短腿，表情夸张；线条与配色在桌面约 300 px 高度下清楚。参考现在桌宠的整体比例和可爱程度，但不复制任何人物。
- **身份**：保留鲸鲸的识别特征：深蓝渐变长发、鲸鳍耳、呆毛、女仆头饰与围裙、鲸鱼标志、鲸尾。负责人 2026-11-07 已允许使用官方徽标，围裙上的标志保留（以 AGENTS.md 为准，覆盖 T6 §2 旧的“不放 logo”）。
- **为动画而设计**：长裙盖住胯部，腿从裙内腿根画起；手臂在袖口处与身体分开；后发、尾巴根、刘海后的额头都要画完整。朝向、画布、坐标严格按 [T6 §2](T6-rig-studio.md)（三分之四侧身脸朝右，2048 画布，中线 x=1024，地面 y=1984）。
- **走路**：采用 Q 版短腿交替摆动，身体每步颠一下，裙摆、尾巴、头发滞后跟随；不画逐帧迈腿。左右方向由程序镜像。转身不在试点范围。

## 素材来源与许可（必须遵守）

- image_gen 允许的参考输入只有：负责人原始参考图 `user-identity-reference.png`、本仓库自绘鲸娘（`characters/deepseek-whale/sprites/`、`rig/textures/`）以及本任务自己生成的定稿图。
- **不得**把 Aboutme（dsh / dsh1）或 Coopanion 大肥鱼的任何帧、贴图、截图作为输入、描摹或图生图参考。新形象按根目录 MIT 随项目公开，这条是公开的前提。
- `pack.json` 的 `credits` 记录每张图的工具、完整提示词、输入图和人工 / 脚本修改；提示词另存 `art/deepseek-whale-q/prompts.json`。

## 步骤

每一步完成后把产物路径写在 PR 评论里，由 Claude 审图后再进入下一步。Claude 的意见具体到图层名和像素位置，Codex 按意见返工，每张图最多三轮；三轮仍不过的列为待负责人决定。

### 0. 登记

从最新协作基线拉 `task/t23-q-whale-rig`，在 `docs/tasks.md` 登记“T23 · Codex 出图 / Claude 审查 · 进行中”。

### 1. 定稿主图（负责人拍板）

- 输出 3 张候选全身主图：2048×2048，按 T6 §2 朝向和坐标，纯色背景 `#00FF00`（若与配色冲突改用 `#FF00FF`，在说明里写明）。
- 同时输出每张候选在 300 px 高度下的缩略图，用来判断桌面上的观感。
- **负责人选定 1 张后才进入第 2 步。** 选定图存为 `art/deepseek-whale-q/master.png`，之后所有图层都以它为唯一身份参考。

### 2. 拆层与补画

- 按 T6 §3 图层清单出图：必需层全部要有；可选层中 `tail`、`ahoge`、`headdress`、`hair_back_curl`、`waist_bow` 也要出（鲸鲸的特征集中在这些部件）。`skirt_sit` 试点不做。
- 做法：以 `master.png` 为输入，用 image_gen **编辑模式**逐层输出“只含该部件、被遮挡部分补画完整”的图，背景仍为纯色。再用 Pillow 脚本做确定性处理：去纯色背景并清理色边、平移配准到主图位置、输出 2048 全画布透明 PNG，存入 `art/deepseek-whale-q/layers/`。
- 透明背景：先试 image_gen 能否直接输出真透明 PNG；能的话可以跳过抠色，但仍要配准。
- 自检脚本 `tools/check_q_layers.py`（新，只用已锁定的 Pillow）：
  1. 按 z 顺序回拼全部图层，与 `master.png` 比较；角色区域内平均色差和最大差异区域写进报告。阈值由 Claude 第一次审图后确定。
  2. 检查边缘：不应有半透明白边或残留背景色。
  3. 检查补画：每个会动的部件按 `rig.js` 的最大角度旋转，检查下层是否露出透明缝。输出极限姿态的合成截图。

### 3. 表情贴片

- 按 T6 §4 出图：`neutral` 四层眼、嘴、眉，以及 `happy`、`love`、`surprised`、`sleep`、`drag`、`dizzy`；`shy`、`smug`、`talk/mouth_open` 试点也一起做。
- 只在脸部区域编辑，眼睛位置必须与 `neutral` 一致（`sleep` 兼作眨眼）。虹膜和高光的留边按 T6 §4，以 `rig_studio compile` 的检查为准。

### 4. Rive 可行性验证（先用占位图，可与第 2 步并行）

用 `tools/make_placeholder_pack.py` 的占位图层，在 `rive/q-whale/` 下建 Rive CLI 项目，逐项验证并把结果写进 PR：

1. Windows 上能否直接安装运行 Rive CLI；不行的话 WSL 是否可用。记录版本号。
2. RML 能否表达：位图部件加网格、骨骼绑定与权重、父子层级、骨骼动画关键帧和缓动、状态机分层与混合、数值、布尔、触发输入。
3. 头发、尾巴、耳鳍的余摆能否实现（脚本、约束或物理），效果不低于 `rig.js`。
4. 本地打包的 Web 运行时能否在本项目的 Qt WebEngine 中渲染：透明背景、像素命中检测（用于鼠标穿透）、60 FPS，并记录空闲 CPU 和内存。
5. 运行时 npm 包的版本、许可和体积。新依赖按 AGENTS.md 先在 PR 里说明理由，再锁定版本。

任一项不能满足，由 Claude 判断：换写法，或者整体退回 `rig.js`（按 T6 §5 写 `pack.json`，用 `rig_studio compile` 输出到 `output/t23-rig/`）。**两条路都不改当前的默认形象来源。**

### 5. 搭建骨骼与动作（Codex 写 RML，Claude 定动作）

- 骨骼层级沿用 T6 §3 的部件和挂接关系，支点位置参考 T6 §5（Rive 中按画布坐标标注）。
- 状态机至少包括：待机（呼吸、眨眼、头发余摆）、走路（按 `walk_speed` 的短腿交替加身体颠动，左右由程序镜像）、被拎起（按 `drag_vx` 摆动）、落地、戳、摸头、说话（按 `mouth_open`）、9 种表情切换，以及思考、干活、庆祝、出错、犯困这几个状态姿势。
- 动作曲线、幅度、缓动、预备与回弹由 Claude 给出参数表，Codex 写入 RML。Claude 看录屏后判断问题出在素材还是参数：素材问题退回第 2 / 3 步，参数问题由 Claude 改参数表。

### 6. 预览与对比

- 加一个独立预览入口（只读环境变量，例如 `AICOMPANION_RIVE=rive\q-whale\out\whale.riv`）。用它启动桌宠，跑 `tools/smoke_pet.py` 和 `tools/measure_pet.ps1`。
- 录制以下片段，每段都与当前 Aboutme 对应动作并排：待机 10 秒、左右各走 120 px、拎起摆动后松手落地、戳、摸头、说话口型、表情连续切换。

## 验收（负责人真机）

1. 负责人看过并排录屏，认为待机、走路、拎起、戳、摸头、说话的顺滑度和可爱程度不低于 Aboutme。
2. 任何动作的极限姿态都没有露缝、断线、色边。
3. `.riv` 由 RML 可重复编译（或退回方案时 `compile` 零错误）；`tools\run_checks.bat` 退出 0，smoke `passed=true`。
4. 空闲 CPU ≤ 3%；内存记录实测值，不在本任务里设新目标。
5. 仓库内没有 Aboutme / Coopanion 素材或由它们导出的文件；`credits` 与 `prompts.json` 完整。

试点通过后另开任务处理：接入角色包、调整形象来源顺序（Aboutme 是否保留为可选）、坐姿和转身、其余互动动作。试点不通过时在本文记录原因，PR 保持草稿，不合入。

## 不做

- 不使用视频生成模型、光流补间或逐帧绘制。
- 不改 `config.py`、`pyproject.toml`；`ui/main_window.py` 只允许加预览入口所需的最少改动，并在 PR 中写明。Rive 运行时之外不新增依赖。
- 不删除 Aboutme 接入和旧自绘素材。
