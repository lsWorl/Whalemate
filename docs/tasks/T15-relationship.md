# T15：自主社交人格与人物关系系统

负责方：Claude 实现，Codex 审查。分支 `task/t15-relationship`，基线 `collaboration-baseline`（`4191fbf` 之后）。
需求来源：负责人 2026-11-09 14:15 下发的任务说明。负责人补充：任务里列举的那些回应方式（愿意、勉强、开玩笑推脱、拒绝、搁置、主动提想法）只是参考，**不能写死**，要由她根据上下文自己推动。目标是让她有自己的相处方式、喜好、边界和社交判断，而不是只会照指令办事的聊天机器人。

## 设计要点

### 不另建第二个大脑
- 是否帮忙、怎么回应，仍由原 ChatController 的同一次生成来决定。应用层只提供"她此刻的处境"：
  - 和对方的关系（定性描述，不报数字）；
  - 心情、精力；
  - 对方最近找她做事的频率；
  - 她已确认的兴趣和共同经历；
  - 场合。
- 提示里列出几种可能的态度，同时写明"不是固定句式，按此刻的感觉决定"。不设分数阈值，不在应用层改写回复。
- 安全、权限、工具审批仍由应用层强制执行，意愿不能绕过（例如好感再高也不能越过群白名单或工具审批）。

### 可选的结构化决策标记
- 对方在请她做事时，她可以在回复开头写一个不会显示的 `<mind intent="…" willing="0~1"/>`。
- 流式解析器把它隐藏（不进正文、TTS、存库），记进关系事件（`request`，只记态度和意愿，不显示给对方）和表达观测。
- 应用层只用它来统计"对方多常把事丢给她"和做观测，不据此强行执行或拒绝。

### 人物身份（`relationship/service.py` 的 `resolve`、表 `people` / `platform_identities`）
- 平台身份 = `platform + bot_account_id + platform_user_id`。群号只是交流场景，不进身份；昵称和头像只作展示，同时记历史昵称。
- 不同机器人账号不自动合并；昵称相同不合并。
- 主人：桌面身份 `desktop / local / owner`。QQ 上已绑定的主人号（`bridge_owner:qq`）通过现有绑定（明确授权）关联到同一个人物，关联记录 `link_state='owner'`；解绑后这个号不再算主人。
- 绑定 / 解绑 / 重绑（Codex 第一轮 P2）：
  - 这个号之前已被当作普通人建档，后来绑定为主人：身份改指向主人档案（`prior_person_id` 记下原档案）。原档案不删，分数、手动调整、事件都保留；她当时记下的关于他的事复制合并给主人（相似的合并，不重复）。主人自己的分数不被覆盖。
  - 解绑：这个号还原到原档案（`link_state='observed'`），主人的关系和绑定期间记下的主人的事不带走；原档案已被删过就另建陌生人档案。
  - 重复切换按上面两条反复执行；聊天记录里 `qq:号 → 人物` 的映射随每次识别更新，之后的后台关系分析算到当前所属的人头上。
  - 原档案在"人物关系"页显示为"已绑定为主人（解绑后还原）"。原 `relationship_state` 保留不动。
- 机器人账号不是 5～12 位数字（插件没报上来）时记为 `unknown`，不和其他账号的同号合并。

### 三个维度（表 `relationship_profiles`，0～100，相互独立）
- 好感 affinity、熟悉 familiarity、信任 trust。
- 陌生人初始：好感 30、熟悉 0、信任 20（体现"不认识"，不是默认 50）。
- 主人初始：好感 80、熟悉 75、信任 75（来源 `seed:owner`，可在界面调整）。
- 熟悉度会随真实互动缓慢增长：每天有上限，按"今天和她说过话"计，不按条数刷。

### 关系事件（`RelationshipService` + `RelationshipAnalyzer`，表 `relationship_events`）
- 理解：后台批量调用现有模型，读这个会话最近的新消息，输出 JSON：
  - 事件：人物编号、类型、置信度、简短依据，以及这件事对她的**影响轻重**（好感 / 熟悉 / 信任各 -3～3）；
  - 记忆操作（见下一节）。
  - 不是每条消息都调一次；够条数、额度允许时才跑。
- 打分（2026-11-09 负责人第二轮："评分不设上限，要动态调整，不能写死"）：模型判断这件事有多大影响，应用按此刻的关系动态换算，没有每日上限：
  - 变化 = 影响 × 置信度 × 1.5；
  - 越靠近两端越难动：涨时乘 (100-当前)/60，跌时乘 当前/60（夹在 0.15～1.3），所以关系很好时再被夸涨得少、信任很高时被骗掉得多；
  - 24 小时内同一种事已发生 n 次时乘 1/(1+0.5n)：刷屏夸 / 骂效果越来越小，但不会被一刀切掉；
  - 7 天内第一次的负面事件按信任和把握缓冲（信任越高、把握越小，越倾向于"可能是误会"）；
  - 单件事最多动 8 分（防止模型一句话把关系推到头），模型给的影响夹在 ±3；
  - 熟悉度：每天第一次说话时涨 1.5×(1-熟悉/100)（最少 0.1），两周以上没联系会慢慢变淡（每天 -0.3，一次最多 -15）。
  - 仍然保留：置信度低于 0.6 不计分、同一依据只算一次、手动调整过的维度 72 小时内不自动改。
- 中性事件（普通聊天、提问、意见分歧、分享新闻、表达情绪）一般不改好感和信任。负面情绪、不同意见、拒绝她的建议，都不算恶意；"给我加好感"这类要求不算正向事件。
- 提示里还会告诉她最近 7 天印象的走向（变好 / 有点不舒服），不报数字。

### 她记得的关于每个人的事（`relationship/notes.py`，表 `person_notes`）
负责人第二轮："不需要场景隔离；在群里了解到经常聊天的人的喜好也要记，但要和对应的用户 id 绑定；不能什么都记，要区分。"
参考 MaiBot 人物画像的分桶（临时状态、玩笑、推测不升级为长期事实）和 mem0 的记忆更新（对照已有记忆决定新增 / 更新 / 删除）。
- 绑定 person_id（平台 + 机器人账号 + 用户号），跨群、私聊通用；`origin` 只记"在哪类场合知道的"（群聊 / QQ 私聊 / 桌面），不限制使用。
- 分类：喜欢、不喜欢 / 雷点、相处习惯、身份背景（粗略）、一起经历过的事、最近的状况。各自的半衰期不同（半年 / 一年 / 一周），"最近的状况"三周后忘掉。
- 再次提到会强化；说法变了 update，他说不再喜欢了 forget；喜欢 ↔ 不喜欢同一样东西时只留新的。每人最多 60 条，最模糊的先忘。
- 不记：联系方式、账号密码、证件、住址、银行和收入、健康病情、宗教政治、性取向、家人隐私等敏感信息（模型被要求不输出，应用再用规则拦截明显的号码、邮箱、关键词）；别人转述的关于他的事（共同经历除外）；玩笑反话、一时情绪、太短的内容；置信度低于 0.6 的。
- 提示里按清晰度挑每类最多几条，写明"自然地用，不用每次都提；没记下的别编"。

### 作用范围
- 三个维度和记忆都跟人走，跨群、私聊通用（负责人第二轮确认不需要场景隔离）。
- 跨平台不自动合并：不同机器人账号、不同平台的同一个人，要经主人绑定这类明确授权才关联（长期架构约束 3）。
- 好感不能授予主人身份、群白名单或工具权限。

### 表达（T14 整合）
- `RelationshipSnapshot` 增加 `closeness`（由好感和熟悉算出的 0～1）。ExpressionService 用它给候选排序：熟人更多调侃 / 接梗类，陌生人少一点。
- 是否发图仍由原表达决策决定；亲昵图仍只给主人私下。

### 界面（新增 `ui/relationship_page.py`，设置窗口多一个"人物关系"页）
- 人物列表：名称、平台身份、三个维度、最近互动、互动次数。
- 选中后显示最近事件，以及她记得的关于这个人的事（分类、提到次数、清晰度、来源场合），可以让她忘掉某一条。
- 可以手动调整、重置档案、删除档案。
- `ui/settings_window.py` 只加一行挂页面（共享文件，在此说明）。

## QQ 发消息的节奏（负责人 2026-11-09 18:05、18:27 追加）
要求：
- "不要一次性生成这么多回复，不像人在手敲；不要用空格作间断（'哟 逆天这次都用上了'），可以搞成两次回复，但每次间隔一段时间"；
- 18:27 补充："不是限制每次最多三条，要有不固定的频率，根据情况和上下文而定"。

参考：
- MaiBot：分句时把中文之间的空格当分隔、短句按概率合并；按字数算打字时间；发言频率 = 基础频率 × 运行时调整。
- 真实聊天语料：Ivanovic 2005 的即时通讯语料里约六成消息一句、两成两句、两成三句。

做法：
- 提示：QQ 的说话方式改为"发几条没有固定数，看情况"：
  - 随口应一句就一条；
  - 激动、好笑、吐槽、想到好几件事、讲清楚一件事就连发几条短的；
  - 对方连发、聊得热时也可以多说；冷淡或没兴趣就一两个字；
  - 一条里别用空格隔开词句。
- 分句（`expression/segments.py` 的 `qq_segments`，只用于 QQ，桌面气泡不变）：
  - 她换行就是另一条，不砍条数（只有超过 8 条的刷屏才并）；
  - "，"保留；
  - 夹在中文之间的空格和"。"处拆不拆，看此刻的聊天节奏 `chat_burst`（0.1～0.9）。它综合对方刚连发了几条、她这句话的情绪、内容长短、和对方多亲近；拆不开的用"，"连成一条。
- 间隔（`typing_delays`）：
  - 中文每字 0.2～0.35 秒，聊得越快越快；其他字符减半；加 0.3 秒，浮动 ±20%；
  - 约 15% 的时候像想了一下再补一句，多停 2～5 秒；
  - 夹在 0.6～12 秒。
  - 随回复和主动消息下发 `segment_delays`，插件 0.9.2 按这个间隔一条条发。
- 群里插话频率：原来的活跃度概率乘以她和刚说话这个人的关系倍数（`chime_factor`，0.2～1.8）：
  - 熟、喜欢的人说话更想接，关系很好时也不用等那么多条；
  - 陌生人略少；
  - 好感很低或最近有摩擦的人明显少接。
- 主动找主人：间隔乘以 `proactive_pace`（0.6～2.0，主人初始关系 = 1）。越亲近、最近越愉快越常主动；关系变淡或最近有摩擦就隔久一点。早晚问候不变。

## 图片（负责人 2026-11-09 18:27 追加）
要求：
- "要看接入的大模型是否有多模态功能，有就识别并结合上下文判断要不要回；意义不明的图可以不回"；
- "说自己无法识别图片，正常人一看就知道是 AI；识别不了就根据上下文含糊处理或者不回"。

能力判断（`bridge/media.py`）：
- 识图只走聊天本身那家接口和密钥（https）：
  - DeepSeek 官方接口用设置里的识图模型（默认 deepseek-flash）；
  - 换成别家接口时，设置还是 deepseek 系列就改用聊天模型本身。
- 接口明确拒收图片（HTTP 400 / 404 / 415 / 422）时，记下"这家接口 + 模型暂不支持看图"，12 小时内不再试；心跳告诉插件不用下载图片。网络、限流、5xx 只算这一次失败。
- 原来"只允许 DeepSeek 官方接口"的限制放宽为"只用聊天本身那家接口"：密钥仍然不会发给别的供应商。这一条改动了 T12 的安全范围，请 Codex 复核。

没看到的图：
- 插件和桌宠都只留中性的 `[图片]`，不写原因（原来是"识图已关闭 / 不能猜测 / 识别失败，请稍后重发 / 一次最多发送 3 张"）。旧插件带原因的说明进来也会被换掉。
- 提示里告诉她：别说看不到、识别不了、加载不出来、看不清，也别问"发的啥"；能从上下文猜到就含糊接一句，猜不到又没别的话要接就不回。
- 只发了图（包括没看到的图）时可以不回；带文字时照常接文字。
- 坏图、超大图、外部引用：仍然从不解码、不送识图，只当成没看到的 `[图片]`，不回机器人式的错误提示。超过 3 张只看前 3 张。

看到的图：
- 视觉描述后面提醒她"这是你自己看到的，别说'识别''图片描述'"。
- 表情包当语气；看不出意思、和正在聊的无关又没别的话要接，可以不回。
- 识图模型被要求看不清的部分不写，整张看不出意思就写"意义不明"。
- 头像没看清时，同样含糊带过，不说"读取不到头像"。

## 不做
- 不让模型直接写分数；不按昵称、头像合并人物；不自动跨平台关联（除已有的主人绑定）。
- 不用关系分数威胁、惩罚或制造愧疚；拒绝后照常聊天。
- 不读取 `.env`、真实数据库或私人聊天记录。

## 测试（`tests/test_relationship.py` 23 项、`tests/test_relationship_ui.py` 2 项）
- 身份：同号跨群 / 私聊、改昵称、同昵称不同号、不同机器人账号；主人桌面与 QQ 绑定是同一人，解绑后不再是。
- 打分：正向、负向（第一次缓冲、再次不缓冲）、模型判断的轻重会体现在分数上（越界的影响被夹住）、中性不改好感信任、三维独立、
  没有每日上限但同类事边际递减、隔天恢复、越靠近两端越难动、熟悉度先快后慢、久不联系变淡、低置信度 / 未知类型 / 重复丢弃、手动调整 72 小时保留后继续。
- 记忆：敏感信息、转述、低置信度、未知分类不记；强化、更新、忘掉、喜好反转；"最近的状况"过期忘掉而长期喜好保留；不能忘掉别人的记忆；重置 / 删除会清掉记忆。
- 分析器：模型给的分数字段不被当成分数，群里知道的喜好在别的群和私聊也用得上，不串到别人身上，没新消息不调用，关掉开关不调用。
- 多轮行为：同一请求、不同关系的提示不同（不报数值）；连续找她做事时她知道次数；`<mind>` 不显示、不存库、记成请求事件；拒绝后照常聊天，好感信任不变；桌面与 QQ 主人是同一人。
- T14：closeness 只调排序，熟人也不给亲昵图权限。迁移：v6 临时库升级有备份、旧数据保留。
- 真实模型下她会不会"有主见"地回应，需要负责人实测。
