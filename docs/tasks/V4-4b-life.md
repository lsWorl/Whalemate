# V4-4b 自己的生活：按兴趣去看、来分享、等回应（桌面优先）

负责：Claude 实现，Codex 审查。分支 `task/v4-4b-life`，叠在 #46（统一主动调度）之上。schema 13→14。

## 一次完整的陪伴循环（计划书 v4 功能四）

1. **按兴趣去做一件事**：
   - 兴趣来源：先用人格包里的兴趣（“人格”页可改）；人格没写时用默认的几样，例如深海和鲸鱼的冷知识、AI 新鲜事、游戏和动画、新梗、吃的。
   - 怎么挑：最近三天看过的兴趣往后排。
   - 这一版的活动只有“读”：用这个角色的联网搜索（和查梗共用每天的搜索次数）搜这个兴趣。
2. **形成自己的看法**：
   - 一次小的模型调用（用途 `life`，按后台分析的思考策略）。只根据搜到的标题和摘要写两句看法，判断值不值得说（0～1），再想一句开口。
   - 没配模型或额度用完时不调用，只记一句，值得程度给低分，大多不会拿来说。
3. **记下来源**：标题、链接、站点、摘录存进新表 `activities`。
   - 搜不到、关了联网、超额、30 天内看过同一个链接、结果没有正文摘要：都算没做成（failed），不编。
4. **判断合不合适说**：值得程度 ≥ 0.55、24 小时内看的、还没说过的，交给统一调度器。
   - 排位：在心事之后、问候之前（新来源 `share`）。
   - 时机：他在电脑前才说。调度器的每日上限、间隔、没回不开新话题照常生效。
5. **说出去**：意图里带上标题、站点、摘录、她的看法。要求只说这些内容、提一句在哪看到的、不说是系统让她来的，说完可以问他怎么看。说出去后活动记为 shared。
6. **等回应**：
   - 他回了：活动记“你回了”，她开心一点（被夸，力度 0.4）。
   - 他没回：按调度器的规则追一句或算了；3 小时没回记“你没回”，她有一点点委屈。

**节制**：
- 每天最多做 3 件（`life_daily_activities`），两件之间至少隔 2 小时。
- 安静时段、专注模式、通话中不做。
- 设置 `life_enabled` 可整体关掉。
- 活动在后台线程里做，不挡界面。

**界面**：“主动与提醒”页的“自己的生活”替换原来的占位卡片，有三部分：
- 开关；
- 每天几件；
- 她最近在做的事：时间、兴趣、状态、你回了没、标题（可点开来源链接）、她的看法。所有文字都经过转义。

## Codex 第一轮（27b8f74）P2 的修复

- **关掉“自己的生活”后仍会分享已完成的活动**：`LifeService.shareable()` 和调度器的分享来源都检查总开关，关掉后一件都不挑，活动历史照样保留。
- **后台正在做时关掉**：
  - 搜索期间关掉：不再调用模型，记为 cancelled（“你关掉了，没看完”）。
  - 思考期间关掉：结果照样记下，但标成 quiet（“看完了，不拿来说”），以后重新打开也不分享。
- 新增 `SwitchOffTests` 2 项回归。
- 同时合入 #46 第一轮修复（选中即占位、QQ 私聊算刚说过话、追问受间隔约束）。分享在确认说出去后才标 shared。

## 怎么验证

`tests/test_life.py` 覆盖以下情况：
- 有来源才算做过，看法写进记录；
- 搜不到、没摘要就是 failed；
- 没模型时值得程度低、不拿来说，同一链接不再算；
- 每天上限、两件间隔、安静时段、开关；
- 人格兴趣与轮换；
- 走统一调度器的分享闭环：他不在电脑前不说；说了记 shared；他回了记 answered，心情加“被夸”；
- 设置卡片列出来源链接、转义、保存。

## 没做 / 没验证

- 活动只有“读”。在群里学新梗、写一小段东西、她慢慢积累的偏好（越聊越喜欢的话题）：后续。
- 分享到主人 QQ：调度器已能按原规则走 QQ，但分享时桌面上的“他在电脑前”判断不适用于 QQ，后续单独调。
- “你上次提到的事自己接上”（主动接话）：后续。
- 没有调用真实搜索和模型看效果；没有 Windows 真机。

## 合入 #46 第三轮修复后的衔接（2026-11-12，Claude）

- 结果未知（`unknown`）的主动消息三小时没动静记为 `dropped`（终态、不记委屈）。不能沿用 `let_go`：本 PR 起 `let_go` 只表示不再追问，还会继续等到三小时结算成 `answered` / `ignored`。
- 分享记为“说过”时，活动 id 从 key（`share:<id>`）取，不依赖 payload。重启后按 `qq_outbox` 对账时 payload 已经没有了。结果未知的分享和心事一样不再重发。
- 关掉“自己的生活”的撤回点有两个：交给插件之前（`take_outbox`），以及插件来领取时（`outbox_claim`）。插件领取以后就不追回了。

## Codex 第三轮复审（3ecdf25）的修复（2026-11-12，Claude）

1. **代码块和引用里的 `<task>` 不算委托**：`CueStream` 会跟踪 ``` 代码块、`行内代码` 和行首 `>` 引用。这些地方的内容原样保留，不解析标注，跨 token 拆开也一样。正常的委托不受影响。
2. **主动开口那一轮不记关系**：`ChatController._after_turn(proactive=True)` 这一轮里，对方什么都没说，所以 `<mind/>` 的判断不写进主人的关系档案，也不推动心情、不触发关系分析。
3. **桌面分享在第一处可见输出前可以撤回**：`MainWindow._still_wanted` 在第一个字或第一张图显示之前再检查一次。如果已经不该说，就撤回这一轮：取消生成、藏起占位气泡、从聊天记录拿掉，并记为没说出去。已经显示出来的不追回。
4. **开关记住“中途关过”**：设置页保存时调用 `LifeService.set_enabled`，关掉时记下 `life_off_at`。进行中的活动和已选中的分享都用 `switched_off_since(开始 / 选中时刻)` 判断，先关后开也会撤回或标成 `cancelled` / `quiet`。
5. **桥接重启后照样拒绝领取**：`ProactiveScheduler.turn_still_valid` 只凭库里 `outreach_log` 的来源和选中时刻判断。桥接在交出前、领取时都会加上这层复核。
6. **确定没发出时撤回“分享过”**：结果未知时先标上，之后补到失败回执就用 `LifeService.unshare` 撤回。
7. **partial 不算文章分享过**：只有全部发出（sent）才标记。寒暄本身的调度记录照样算一次、照样防重。
8. **放下未知投递的时刻要重新记**：从 unknown 变成 dropped 时，`settled_at` 记成放下的这一刻，之后照样隔满间隔再开新话题。
9. **一条回复只算给一个话题**：等回应的截止时刻取“三小时”和“她之后又主动说了另一件事”两者中较早的。同一话题的追问不算换话题。
