# V4-2：人格包（计划书 v4 功能二，阶段二第一项）

负责：Claude 实现，Codex 审查，负责人在 Windows 真机上验收。分支：`task/v4-2-persona`，叠在 #33（界面翻新）上。

## 要做成什么

同一个她可以换上不同的性格；共同经历、关系、表情包习惯、办事记录都保留。

## 设计

- **数据**：`domain/persona.py` 的 `Persona`。内容包括：
  - 人格名称、角色设定、说话风格、背景；
  - 说话示例（最多 12 条）、兴趣（给功能四用）；
  - 情绪倾向：容易不高兴、消气快，取值 0～1（给功能三用）；
  - 世界书：关键词命中才带上，也可以设成“每次都带”；
  - 作者备注：不会发给模型。

  人格是纯数据，不含脚本，不带 Key 和模型配置，也**不含名字**——名字属于角色身份（长期架构约束 1、2）。外来内容都经过 `normalize`：去掉控制字符，每个字段有长度上限，未知字段丢弃。
- **存储**：schema 8→9，新增 `personas`、`persona_versions` 两张表。当前人格记在 `app_settings` 的 `active_persona:<角色>`。每次保存留一个版本，每个人格最多保留 30 个，内容没变不留。
- **生效方式**：角色表的 `description / speaking_style` 始终等于当前人格的同名字段。桌面、QQ、语音、办事原本就读这两项，切换后下一句就用新性格。背景、示例和命中的世界书由 `ContextService` 插在“说话风格”之后、“当前心情”之前。切换和保存后，聊天控制器手里的角色对象会同步更新。
- **内置人格与角色包升级**：
  - 角色包的人设就是内置人格，不能删。
  - 用户没改过时，角色包升级会更新它（并留一个版本）。
  - 用户改过时不覆盖，界面提示“内置版本有更新”，可以一键恢复原文。
  - 首次启用时，如果角色表里的设定和包里不一样（以前改过），另建一个“我改过的版本”作为当前人格，原文作为内置人格保留。
  - 自建角色没有角色包，会建一个“默认”人格。
- **导入导出**：
  - 导入：本项目格式（`AICompanionPersona` JSON）；SillyTavern `chara_card_v2/v3` JSON；PNG 角色卡（tEXt / zTXt / iTXt 里的 `chara` 或 `ccv3`，不解码图片）。
  - 字段对应：description + personality → 角色设定，scenario + system_prompt → 背景，first_mes + mes_example → 示例，tags → 兴趣，character_book → 世界书（禁用的条目不导入）。`{{char}}` 换成“你”，`{{user}}` 换成“对方”。
  - 导入总是新建一个人格，不覆盖已有的，也不自动切换。
  - 导出：本项目格式，或 SillyTavern v2 JSON；只含人格本身，不含聊天记录和记忆。
  - 文件上限 4 MB。
- **界面**：设置 → 角色与形象。“她是谁”卡片只留名字；“人格”卡片里可以选择人格、设为当前，“管理”菜单有新建、复制、删除、导入、导出和历史版本。编辑器按上面的字段排列。会实时显示大约占多少字和词元，超过 6000 字时提示可以挪进世界书（初始值，只提示，不替用户删改）。“预览她会怎么说”按编辑中、还没保存的内容让聊天模型回一句（后台线程，会产生少量用量）。

## 验收

- 新建一个人格并设为当前：下一句话语气变了，记忆、关系、名字都没变；QQ 里也是新人格。
- 改几次以后从历史版本回退；回退前的内容也会留一个版本。
- 导入一张 SillyTavern PNG 角色卡：字段对上，`{{char}}` / `{{user}}` 已经换掉，没有自动切换。
- 导出后再导入，内容一致。
- 人格写得很长时出现提示。
- 改过内置人格以后升级角色包：自己的修改还在，并提示有新版本。
