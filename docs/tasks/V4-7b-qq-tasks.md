## 主人私聊

在桌面“聊天平台”设置主人 QQ，新版插件心跳提供机器人的 QQ。发起交办、领取私聊通知、回复审批和执行工具均核对机器人、主人账号和关联到桌面主人的 bound 身份。旧库在 schema 17 → 18 的事务中保留绑定设置、关系、任务、聊天及附件。首次新版心跳确认机器人后启用交办。

文字沿用聊天的同轮 task 标记和桌面“要我动手吗”确认。QQ 开始、执行和继续任务的审批均与桌面共用一项。回复“同意 编号”或“拒绝 编号 原因”。一次性短号在 120 秒后过期。先答的一端结算，桌面刷新，插件在下一次心跳尝试撤回失效审批。超过平台撤回期时，旧编号也无法执行。机器人、主人和平台消息号持久去重。开始、完成或失败会发给主人，长结果提示“详细见桌面办事记录”。程序关闭时仍在线的 AstrBot 可返回办不了的提示。

## 附件和协议

插件 0.12.0 在已有令牌协议上增加 task_protocol=1、附件授权查询、附件上传和通知领取。普通聊天沿用原请求体上限。旧插件继续聊天。群聊与其他私聊的文件无法发起本机操作。

插件先向桌面申请取文件，再以 NapCat 的文件编号读取平台缓存或字节。桌面校验文件名、格式与解码后体积。最多 16 件，每件 4 MiB，合计 16 MiB。用户的 QQ 文件名记录为来源标签。副本、哈希、图片识别、上下文预算、暂停恢复和回收沿用 V4-7c。DOCX/XLSX 以 64 KiB 为上限分块读取，每个文档累计实际解压字节数。

测试使用临时库、真实桥接服务和模拟平台、模型，覆盖身份矩阵、撤销绑定、双端竞答、超时、重复投递、附件恢复、旧库迁移和撤回 API。真实 QQ、真实云端办事与平台撤回结果待人工验收。Windows 命令及结果见本 PR 和实施记录。
